# CLEC native Phase 2 corrective issues

This ledger records confirmed Unit A defects found during independent review of heads `f4d04a7` and `d2b62ea` and tracks each verified fix.

## Unit A findings and resolutions

1. **`P2-DETERMINISM-CANONICAL-MAP`: `clec-publish` produces non-deterministic SQLite and `.zst` hashes across identical runs.**
   At `f4d04a7`, `native/src/snapshot.rs` builds `groups: HashMap<(String, SourceRole, String), Vec<usize>>` and iterates `groups.values()` when inserting rows into `source_canonical_map`. Three identical synthetic builds with multiple equivalence groups produced three distinct SQLite SHA-256 digests (`847844f4...`, `4df2948d...`, `d1715021...`, recorded in `.cache/before-repro/before_repro.json`).
   **Resolution (`6f1bab0` and fresh retained second build).** `native/src/domain.rs` derives `PartialOrd, Ord` on `SourceRole`, and `native/src/snapshot.rs` replaces `HashMap` with `BTreeMap` and sorts `source_canonical_map` rows by `(work_id, role, equivalence_hash, source_id)` before schema inserts. Synthetic unit tests (`publish_is_byte_deterministic_across_repeats_and_input_permutations`) and `verify_phase2.py` (`deterministic_repeat_publish`) pass. Notice that the prior `full-repeat-check` directory in the `d2b62ea` worktree retained only `manifest-stdout.json`, so the historical second full build claimed at `83f7738` is unverified. A fresh full-corpus build and sync run in `.cache/phase2/fresh-repeat-run/` now retains `corpus.sqlite.zst`, `manifest.json`, synced SQLite, `/usr/bin/time -l` logs, and `fresh-repeat-capacity-report.json`, matching the prior retained first build in `capacity-run/` byte-for-byte (`7e106db6b5f06287d4a8e8d1323af2c5098cc702719f8aa310aa75af8df610a0`, `1,058,476,032` B SQLite; `34a01433e41a7b71e635f4aa1ddac5f6c99a05dcce2a453ae0e9e264a7f73f66`, `327,255,080` B `.sqlite.zst`).

2. **`P2-CAPACITY-DELETED-ARTIFACTS`: Deleted `a409...` capacity-run artifacts leave table-content equality unproved.**
   In the prior worktree's `.cache/phase2/capacity-run/`, the built `.sqlite` and `.sqlite.zst` files for `a4091fa6...` were removed after `capture_capacity.py` ran, even though `capacity-report.json` recorded `"artifactsKept": true`. Aggregate row counts matched `5b14`, but row-level content and posting equality were not verified.
   **Resolution (`83f7738` and fresh `semantic_compare.py` receipts).** `docs/agent-work/clec-native/phase2-report.md` records an honest correction noting that the deleted `a409...` artifacts could not prove table-content equality. Both the prior `capacity-run/` build and the fresh `fresh-repeat-run/` build retain the deterministic `7e106db6...` release, synced SQLite DB, and `/usr/bin/time -l` logs. The updated `evaluation/clec-v1/phase2/semantic_compare.py` with `clec-validate` native structural validation proves both content equality (`10` domain tables and `37,690,846` FTS5 postings, digest `f1d51579b655c3a170e34972aba00120b81da57c0a928891875f1ecbbea09cc0`) and native structural validity for both the preserved `5b14` reference DB and the fresh `7e106db6` DB (`usableSemanticEquivalence: true`, source files byte-identical).

3. **`P2-CAPACITY-MEASUREMENT-CONTRACT`: `3.0016 GB` figure is a scoped component estimate, and `capture_capacity.py` sets only `TMPDIR`.**
   At `f4d04a7`, `capture_capacity.py` sets only `TMPDIR` (omitting `SQLITE_TMPDIR`, `TEMP`, `TMP`), walks directories for logical byte size only (omitting allocated disk blocks), and labels `sqliteBytes + 2 * postingBucketSetBytes + 65536` as a conservative worst-case storage bound without listing excluded SQLite journals, temp B-tree spills, filesystem allocation slack, and OS buffers.
   **Resolution (`83f7738`).** `evaluation/clec-v1/phase2/PROTOCOL.md` and `evaluation/clec-v1/phase2/capture_capacity.py` now set `TMPDIR`, `SQLITE_TMPDIR`, `TEMP`, and `TMP` explicitly inside the measured temp tree, report both logical bytes and allocated disk blocks (`st_blocks * 512`) as `polled_50ms_sampled_lower_bound`, extract `estimate_posting_buckets_bytes` cleanly without narration comments, and separate `scopedComponentStorageEstimate` with explicit `uncoveredOverheads`. All `14` baseline workspace hashes under `/Users/century/vibing/clec` remained unchanged before and after both retained capacity runs.

4. **`P2-SEMANTIC-COMPARE-FTS-SHADOW-VALIDATION`: `semantic_compare.py` ignored FTS5 `search_data` global statistics and `search_docsize` document lengths.**
   At `d2b62ea`, `evaluation/clec-v1/phase2/semantic_compare.py` compared `10` domain tables and `fts5vocab` postings while skipping FTS5 global statistics (`search_data`) and document lengths (`search_docsize`), which affect BM25 scoring. On copies of a valid synthetic DB, both `UPDATE search_data SET block=X'000000' WHERE id=1;` and `UPDATE search_docsize SET sz=X'0000' WHERE id=1;` yielded exit `0` and `semanticallyEqual: true` (`.cache/before-repro/semantic_compare_before_repro.json`).
   **Resolution (Unit A closeout).** `native/src/snapshot.rs` adds `validate_sqlite_snapshot` (copying the target file read-only into an isolated temp staging directory and invoking `CorpusStore::open_readonly` plus `CorpusStore::validate_staging_db`), exposed via internal developer binary `native/src/bin/clec-validate.rs` so the public `clec` CLI surface remains unchanged. `evaluation/clec-v1/phase2/semantic_compare.py` now separates logical `contentEqual` from per-side native `structuralValidity`, binds validation receipts to actual DB byte lengths/SHA-256 hashes, validator binary SHA-256, format/revision identity, and git state, preserves `contentEqual` with `usableSemanticEquivalence: false` when validity is inconclusive, rejects both FTS shadow corruptions (`INTEGRITY_MISMATCH`) and stale/mismatched receipts while keeping source DBs byte-identical, and accepts physically different `VACUUM`ed DBs when both pass native validation.

5. **`P2-UNVERIFIED-REPEAT-BUILD-PROVENANCE`: `full-repeat-check` in the `d2b62ea` worktree contained only `manifest-stdout.json`.**
   Docs at `d2b62ea` claimed two sequential full builds produced `7e106db6...`, but `.cache/phase2/full-repeat-check/` retained only `manifest-stdout.json` with no `.sqlite.zst` artifact, synced `.sqlite`, or logs.
   **Resolution (Unit A closeout).** `docs/agent-work/clec-native/phase2-report.md`, `evaluation/clec-v1/phase2/PROTOCOL.md`, and `.audit/f4d04a7-fixes.tsv` mark the historical `full-repeat-check` second-build claim unverified. A fresh full-corpus `capture_capacity.py --keep-artifacts` run in `.cache/phase2/fresh-repeat-run/` retains `corpus.sqlite.zst` (`327,255,080` B, SHA-256 `34a01433e41a7b71e635f4aa1ddac5f6c99a05dcce2a453ae0e9e264a7f73f66`), synced SQLite (`1,058,476,032` B, SHA-256 `7e106db6b5f06287d4a8e8d1323af2c5098cc702719f8aa310aa75af8df610a0`), `/usr/bin/time -l` logs, binary/code hashes, and verified 14/14 baseline workspace input hashes matching the prior retained `capacity-run/` build byte-for-byte.
