# CLEC Native Phase 2 Report

Phase 2 implements conservative work grouping, deterministic cross-format duplicate collapse inside `clec_core`, normalized canonical membership (`clec-native-v2`), bounded-memory full-corpus publishing and staging validation, full inventory reconciliation against the 0.3.0 snapshot, and a rerunnable Phase 2 verification suite.

## Implemented changes

- **`native/src/domain.rs`.** Upgrades `CORPUS_FORMAT` to `clec-native-v2` (rejecting legacy revisions 1, 2, 3, and `clec-native-v1`), persists `TOKENIZATION_REVISION`, `NORMALIZATION_REVISION`, `DICTIONARY_REVISION`, and `EQUIVALENCE_REVISION`, adds `AutomaticUnverified` and `OriginalUnknown` attribution variants, adds `ProjectionKind` and `EquivalenceBasis` validated enums, and adds `select_canonical_index` as the shared deterministic election rule.
- **`native/src/ingest.rs`.** Adds `compute_equivalence_projection` for subtitle cue payloads (`srt`, `str`, `vtt`), recognized `# 語音筆記：` plus `## [ts – ts]` archive Markdown files, and plain text with documented Unicode whitespace folding and no OpenCC, punctuation deletion, or semantic normalization.
- **`native/src/store.rs`.** Adds `source_canonical_map` and `canonical_sources` counts, validates canonical election and zero-passage invariants for collapsed representations, replaces full-corpus in-memory posting maps with partitioned binary buckets (`64` disk buckets when passages exceed `2000`, `1` in-memory bucket for small fixtures) plus per-source streaming validation, exposes `canonicalSourceId` and `equivalentSources` on `read` and `sources`, and adds `--canonical-only` filtering.
- **`native/src/snapshot.rs`, `native/src/cli.rs`, and `native/src/bin/clec-validate.rs`.** Switches `build_in_staging` to two-pass streaming (metadata/blobs/cues first, canonical selection, then passage/FTS indexing on canonical sources only), supports `excluded`, `empty`, `missing`, and `statusReason` intake fields, updates `clec schema` for `phase2` (`cross_format_dedup` enabled; `sag2` and `http_bootstrap` unsupported), updates `--max-bytes` fixed-point output formatting, and adds `validate_sqlite_snapshot` plus internal developer binary `clec-validate` (reusing `CorpusStore::validate_staging_db` on isolated read-only copies without altering `clec`'s public CLI surface).
- **`tools/prepare_phase2_intake.py`.** Deterministically reads collection manifests under `/Users/century/vibing/clec`, groups archive containers (`archive:{id}`), `clectw` episodes (`clectw:{slug}`), `local-asr`/`podcast-asr`, and distinct document/web origins conservatively, preserves unverified attribution labels, reconciles all `12,532` admitted sources and `17,972` inventory items against the 0.3.0 snapshot, and reports unmerged cross-work duplicate candidates (`55` groups).
- **`evaluation/clec-v1/phase2/PROTOCOL.md`, `verify_phase2.py`, `capture_capacity.py`, `semantic_compare.py`, and `test_capture_capacity.py`.** Adds the Phase 2 verification protocol, the `10`-suite blackbox driver (covering all Phase 1 regression invariants, deterministic repeat builds, synthetic triples, false-friend non-merge controls, canonical tampering guards, `00318`/`00575` canonical collapse, and the `2,001`-passage `64`-bucket negative regressions), the single-run capacity capture tool (`TMPDIR`/`SQLITE_TMPDIR`/`TEMP`/`TMP`, logical + allocated blocks, sampled lower bound, and scoped component estimates), and `semantic_compare.py` (separating logical content digest equality from `clec-validate` structural validity bound to actual DB bytes and validator binary/code identity). Also fixes `native/src/bin/clec-publish.rs` `--help` output to derive from `CORPUS_FORMAT` (`clec-native-v2`) and removes two narration comments from `tools/prepare_phase2_intake.py`.

- HTTP manifest/artifact bootstrap (Phase 4), SAG2 synthesis (Phase 5), and cross-OS Linux/Windows verification (Phase 6) remain unimplemented and out of scope.

## Post-review corrections (`f4d04a7` audit)

Independent review of head `f4d04a7` confirmed three defects in the Phase 2 build and reporting record:

1. **Deleted `a409...` capacity artifacts and unproved table-content claim.** The `.sqlite` and `.sqlite.zst` artifacts produced during the `a4091fa6...` run (`39a12b7`) were removed after capture, leaving only `capacity-report.json` and the `/usr/bin/time -l` logs. Because those artifacts are absent and only aggregate counts were compared, the prior claim that all table row contents matched `5b14` is unproved.
2. **Scoped component estimate vs. full filesystem upper bound.** The `3,001,600,396` B figure covers only `sqliteBytes`, `compressedZstBytes`, two `PostingBuckets` sets, and a `65,536` B allowance. It excludes SQLite rollback/WAL/SHM journals, SQLite temp sort files, filesystem block-allocation slack, and OS temp buffers. The `50` ms directory poll captures a sampled lower bound on transient disk usage, not a mathematical upper bound.
3. **Non-deterministic `source_canonical_map` insertion order.** `native/src/snapshot.rs` iterated a `HashMap` of equivalence groups before inserting rows into `source_canonical_map`, producing distinct `corpus.sqlite` and `corpus.sqlite.zst` SHA-256 digests across identical runs.

Fixes, retained deterministic full-corpus artifacts (`7e106db6...`), and the streaming semantic digest comparison against `5b14` are recorded in `docs/agent-work/clec-native/phase2-issues.md`.
