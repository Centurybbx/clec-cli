# Contracts

Intake JSON: `{ "schemaVersion": 1, "sources": [...] }`. Each entry requires `path`, `title`, `type` (`document`, `qa`, `transcript`, `curated`, `metadata`), `quality` (free explicit provenance label), and `status` (`ready`, `quarantined`, `unsupported`, `metadata_only`). Optional `date` (YYYY-MM-DD), `dateBasis` (required with date), `origin` (original asset path or URL). Paths are workspace-relative and must resolve inside the workspace; symlinks outside it are rejected. Only .txt/.md UTF-8 files are admitted in this slice. An intake manifest is an explicit authority boundary, not an assertion that every ready source is verified.

Source version: stable source ID from workspace-relative path; content hash from original bytes; version hash additionally binds title/type/date/date basis/quality/origin. Generation binds the complete intake and segmentation revision. Original text stored separately from search-normalized text. Missing/empty/quarantined/unsupported/metadata assets appear in inventory with their reason.

Section: stable ID binds source version, original half-open offsets, order and boundary basis (`whole`, `heading`, `contiguous`). Passage: stable search locator maps to exactly one Section and its original offsets. Independent same-source Sections remain independent candidates. Neighbour reads disclose every included Section; whole-source reads obey the same hard read budget. No fabricated summaries.

Citation: reader-issued per-run C ID, generation, source ID/version, section ID, exact whole-read original UTF-16 range and quote. C IDs are host-only identities; model input uses separate fresh namespaced read/evidence handles. The reader retains its search allowlist and revalidates every final cited original. C IDs remain stable, so a result using only C3 keeps C3. Successful structural/source-integrity validation does not prove entailment; Terra assesses fidelity.

Search: original question preserved; additional traditional/simplified variants derived for retrieval only. Typed lexical queries preserve short terms, fund codes and episode IDs; optional hybrid adds vector query and QMD reranking. Scores rank candidates only. HTTP errors, malformed results, generation mismatch and unavailable indexes fail explicitly rather than becoming “no evidence.” Empty successful retrieval yields an honest no-evidence response without a model call.

QA model contract is exactly `{blocks:[...]}`. Answer/context blocks have exactly `{kind,text,evidenceIds}` and require issued current-run evidence handles. Gap blocks have exactly `{kind:"gap",text}`; gaps express unanswered parts or uncertainty, never a factual escape hatch, absence or provenance claim. Unknown fields/IDs, stale handles, model-authored citation markers, malformed/truncated JSON and unsuccessful provider stops fail closed; no repair/retry. One answer portion per block should retain its conditions, but structural validation cannot enforce semantic atomicity or coverage.

Host outcome derives from blocks: answer without gap → `supported`; answer with gap → `partial`; no answer requires a gap → `insufficient_evidence`. Context does not promote answerability and may carry valid contextual citations with an insufficient outcome. The host-only successful empty-retrieval branch returns `no_hits`, `blocks:[]`, canonical text, zero candidates/reads/citations/model admissions; errors and oversized unread sources never become no_hits.

Public result: `{validated:true,answerability,blocks,text,citations,metrics}`. Normalized public blocks carry reader-issued C IDs in `evidenceIds`. The single pure `domain/answer.ts` contract validates blocks, derives outcome, and renders text/markers plus recognized source-quality notes. Notes come solely from retained explicit cited quality labels, in first-citation order, deduplicated by source/version/note kind. Unknown labels produce no assertion; no inferred completeness or verbatim status. Session precommit checks exact recorded read identities, ordered used citation IDs and deterministic rendering. GET/replay/restart preserve the validated result; they do not rerun source/semantic validation.

Events remain `start/search/read/text/citation/complete/error` for stateless CLI. QA and session executors emit only search/read during execution, then return the result after cleanup. CLI emits final text/citations/complete from that return; complete carries `answerability,blocks,metrics`. Sessions atomically commit final assistant message, result, text event, citation events and completed terminal event before publication. Failure/cancel may retain search/read but never final text/citations/assistant output. Text is buffered final output, not provider token streaming. Removed result/completion booleans and status aliases have no compatibility shim.

Default budgets: 600000 ms execution; two searches (one host, one directed supplementary), eight total read attempts including refusals, 40000 original UTF-16 units, four admitted model requests, 2048 output tokens/request, nine tool attempts. Admission remains cumulative full serialized UTF-8 context bytes +2048 reserve/request; no history/original truncation or budget inflation. Independent parser bounds: 65536 raw UTF-8 JSON bytes, 16 blocks, 4096 UTF-16 units/block, 16384 total text units, 64 evidence-reference occurrences. Host markers/recognized notes add bounded deterministic output.

All navigation candidates are projected with actionable `readLocator`, descriptive title/date/date basis/type and explicitly UNREAD previews. `read_evidence` accepts only `{readLocator,expansion}`. IDs in original provenance are metadata, never alternative tool arguments. Identical generation/version/source/section/span reads reuse one current evidence handle; subsequent tool replies reference it without duplicating original text, whose first full projection remains in completed Pi history. A new run issues a different namespace and rejects old handles. Registry snapshots list issued evidence handles and remaining read/search budgets.

Injected bounded local diagnostics contain finite stages/codes/reasons, run/request identity and numeric sizes only. Never payloads, source text, prompts, credentials, arbitrary exceptions/stacks or headers. Public output intentionally includes source citations; diagnostics do not. See [QA contract handoff](qa-contract-handoff.md) for sink semantics and unexecuted real E2E gates.
