# 全库嵌入有界工作与恢复设计

状态：2026-11-11 主审源码调查与设计，未实施、未测试。当前全库真实构建已结束并失败；原失败目录保留作证据。

## 已定位的结构问题

锁定 QMD dist/store.js 的 generateEmbeddings 在一个 withLLMSessionForLlm 内遍历全部 document batches。maxDocsPerBatch/maxBatchBytes 只限制该会话内部的加载批次，并没有限制一次公开 embed 调用的总工作量。因此原有 32 文档/字节上限不能避免整个语料共享两小时寿命。session 过期后跳过后续批次，返回的 docsProcessed 仍取初始 totalDocs，不能用于判断完成。

generation.ts 当前遇到同 id 未完成目录会将它改名为 .failed-*，随后重建，明确不复用 partial build。只修改 QMD 会话寿命不足以实现进程重启后的续做。QMD 现有 chunk batch 事务和 removeIncompleteEmbeddings 可保存完整文档的成果，但不能据此声称任意部分 chunk 可以跨进程正确复用。

这些源码事实解释失效边界，不证明具体吞吐瓶颈；分词、模型推理、SQLite 和并行负载的耗时贡献尚未测定。

## 实施契约（Sol medium）

1. 在锁定依赖的公开 API 边界增加真正的有界工作选择，而不是重复超时直至碰巧成功。一次调用选择有限待处理文档/字节；返回实际处理量、剩余量和是否正常达到批次界限。正常未完成与错误必须区分。单个超大文档需有明确上限/错误，不能无限续跑同一文档。
2. 每个工作单元拥有独立有限会话，明确释放会话；无需每批重新下载或盲目重载模型。透传取消，在安全边界检查；记录批次耗时、完成量和剩余量。无进展应失败并保留证据，不能形成无限循环。
3. CLEC 调度器只使用公开 SDK；有限循环直到完整覆盖，错误立即停止。保留当前模型/fingerprint、typed metadata、文档计数和 partition 检查，未完成不得写 READY/CURRENT。不得对 QMD 私有表增加应用侧 SQL。
4. 恢复使用显式版本化检查点，绑定 manifest、实际来源版本、生成 Markdown、模型/分段/嵌入策略及补丁身份；BUILDING id 一项不足以授权续做。单写锁覆盖恢复。身份不同的状态隔离保留，绝不污染 published generation。优先通过公开 backup/update/health 恢复已完成文档向量；不得直接服用失败 generation。
5. 模块分离为公开 QMD 有界工作能力、CLEC 调度策略、generation 恢复/发布。若需要大范围改变依赖算法或持久化语义，先提交具体设计供主审，不拼接补丁。保持严格依赖哈希门禁、可重复安装及新冻结清单。
