QMD's git `prepare` runs `scripts/install-hooks.mjs` followed by `scripts/build.mjs` (TypeScript compilation and CLI stamping) before npm packs the git dependency. Its package files include `dist/` but exclude `src/`; the installed package inspected here contains no source tree. Root `postinstall` checks the exact manifest pin, lock pin/resolution and installed version, requires every touched file to match the reviewed pristine hashes, invokes `patch-package --error-on-fail --error-on-warn`, and checks every patched output hash. Only an entirely exact already-patched set is accepted on repeat installation. Mixed, changed, missing or newly compiled different inputs fail installation rather than applying a nearby hunk or silently using another SDK. Update the pin/patch/hash inventory together after explicit review. npm may canonicalize GitHub git resolutions to SSH when updating a lockfile; restore the explicit reviewed HTTPS resolution before installation, or the guard rejects it.

## Public API contract

`QMDStore.embed(options)` now declares and forwards `maxDurationMs?: number` to the already existing internal option. Upstream semantics remain: omitted means 30 minutes, <=0 disables the timer, the cap covers the whole session including chunking, and expiry can skip complete later batches without reporting an error for them. CLEC does not permit disabling it. No new batching SDK, internal access, deep import, private SQLite query, retries or fallback was added.

`QMDStore.getIndexHealth()` now additionally returns `missingVectorPartitions: number | null` through the root-exported `IndexHealthInfo` type. It uses the existing `vecLayout`, `vecTableReadable` and `missingPartitionRows` helpers inside QMD: null if the partitioned vector index is absent/unreadable; otherwise the number of active `(hash, chunk sequence, collection)` registrations missing from its partition metadata. This is independent of `needsEmbedding`, which checks active hashes against the configured current model/fingerprint and expected chunk counts in content_vectors. Partition coverage does not by itself prove model/fingerprint completeness, so both checks are required. The existing partition checker covers registrations; it is not an exhaustive forensic audit of arbitrary physical vector-table corruption or vector semantic quality. A schema-only vector-index existence flag alone is insufficient; the health extension also probes readability.

Ingestion requires exactly one registered destination collection, matching final Markdown path and expected active passage count. Public metadata discovery still requires typed sourceId/sourceType/sourceVersion on every passage. Public status additionally requires the same sole active collection/path/document total and zero pending metadata extraction. Hybrid builds additionally require `hasVectorIndex === true`, both public status/health `needsEmbedding === 0`, matching health active-document total, and `missingVectorPartitions === 0`. Missing/unavailable values fail closed. These global model and partition checks cover the destination because the sole-active-collection invariant was checked first. Future multi-collection designs must change this policy deliberately.

`docsProcessed` is upstream's initially selected pending-document count, not an independent completion proof. Existing `update.vectorsCopied`, `embed.chunksCopied`, `chunksEmbedded`, failures and duration metrics remain separate and unchanged; no aggregation/relabeling hides incomplete work. Full coverage, not counters alone, authorizes build completion.

## Ingestion policy, identity and cleanup

`backend/src/ingestion/embedding-policy.ts` owns the explicit two-hour embedding-only default (`7,200,000 ms`), regex chunking and existing 32-document / 1,000,000-byte memory limits. Its validator accepts only positive safe integer milliseconds up to Node's signed 32-bit timer maximum; zero, negative, NaN, Infinity, fractional and overflowing timers are rejected. There is no QA/config/environment budget change. The policy function permits a caller-supplied finite duration for future deliberate integration; production currently always uses the default. This removes the known 30-minute ceiling, but does not guarantee completion for arbitrary corpora or impose a hard native-operation wall clock. No repeated embed calls or Promise.race were added.

`embeddingRevision` is now `qmd-regex-batched-public-lifetime-partition-health-v2`. The existing full build-settings key and generation identity include this revision and hashes of installed `index.js` and `store.js` (already included in qmdBuildHashes). Consequently the unchanged original git pin cannot make a pre-patch generation seed a new patched build. Text-derived bundles may still be reused under their separate identity. Subsequent identical patched settings retain the existing vector-copy/zero-new-embedding path. Policy/patch changes require a revision bump; installed artifact hashes additionally bind exact implementation bytes. No generation schema or publication orchestration was changed.

Callbacks and checks still provide cooperative cancellation. Public embed accepts no external AbortSignal; cancellation during chunking/native embedding may wait until the next callback or return, including upstream bounded chunk retry work. A running native batch is not forcibly interrupted by the lifetime timer or CLEC's caller signal. The retired-collection update now has the same progress cancellation check as destination update. No hard cancellation-latency claim is made.

SQLite backup-source closure and QMD closure now preserve an already thrown primary operation/cancellation/coverage error if cleanup also throws. Both closures are awaited/performed before success returns; cleanup failure on the success path rejects the build before publication. Existing generation orchestration still writes READY/CURRENT only after buildQmd returns successfully and its own completion/cancellation checks pass. No original or published generation is opened for writes, and partial staging remains unpublished under the existing quarantine/recovery policy.
