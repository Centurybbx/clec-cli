# Embedding recovery implementation decision

2026-11-11, Sol medium. A linear state machine replaces a generic task framework. The global exclusive BUILD.lock serializes build, clone, exchange and publication; no automatic stale-lock deletion. Checkpoint v1 owns identity and attempt accounting, not a cursor into documents. SDK pending is authoritative, strict complete hashes survive; partial documents remain the QMD embedWork responsibility. No cumulative successful-unit cap rejects remaining valid work: each process is bounded by observed pending and strict decrease, plus inherited 24h time budget.

State graph: fresh -> prepared -> embedding -> closed -> READY -> CURRENT. Only embedding/closed checkpoints can be cloned for recovery. Prepared failure requires manual inspection/rebuild; old marker-only directories fail closed and remain intact. Closed recovery reruns public update/metadata/embedding/health gates and awaits close before publication. generation.json without READY is unpublished and must pass the same recovery path.

Recovery exchange: verified donor -> durable clone (public readOnly SQLite backup for both databases, checked file copies) -> durable exchange intent -> donor renamed to unique retained directory -> clone renamed to deterministic directory -> intent retired. Intent records exact names and checkpoint digest. On restart only the three unambiguous layouts (before first rename, between renames, after second rename) are advanced; all other layouts fail closed. Directory fsync follows each rename. Donor is never opened with QMD or hardlinked.

Before every embedWork, persist attempt number, starting pending and reserved maximum duration. A crash/unknown result consumes that reservation. A settled result replaces reservation with observed elapsed, including callbacks and persistence measured at scheduler boundaries; failure stops the process. After clone/exchange, recovery charges a new preparation reservation before opening the SDK and rerunning update/validation. Clone/evidence verification and process downtime are outside the embedding/SDK budget; no model is opened in those stages. Unobserved SDK work is charged conservatively. Checkpoint and SQLite are intentionally not claimed to be one transaction: a lagging checkpoint may coexist with more complete database hashes.

Identity binds raw intake hash, canonical manifest, admitted source records/byte versions, expected EvidenceStore source bundles, exact generated Markdown path/byte/hash list, counts, complete settings/policy, runtime, QMD installed implementation/declaration hashes and patch hash, embedding URI, actual local GGUF hash and actual SDK fingerprint. HF URI-only builds have no byte identity and cannot authorize recovery. A minimal root re-export of existing getEmbeddingFingerprint is required to bind identity before the first attempt; it changes no model, vector or chunk algorithm. Dependencies remain at the frozen versions.
