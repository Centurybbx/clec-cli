The exact installed dependency is @tobilu/qmd 2.8.3, pinned in `backend/package.json` to `git+https://github.com/tobi/qmd.git#86d2365d17fc682e491c2c53d1e4a884aee8682a`. Context Hub was consulted using `chub --help` and `chub search qmd --json`; there is no QMD documentation entry. The installed package's own README and distributed implementation/types were inspected instead. The packaged README's embed example is insufficient to establish lifetime behavior; the following distributed source is the decisive evidence (paths below are relative to `backend/node_modules/@tobilu/qmd/`):

- `dist/store.js:98`: DEFAULT_EMBED_MAX_DURATION_MS is 30 * 60 * 1000.
- `dist/store.js:1792–2034`: generateEmbeddings obtains **all** pending documents, then creates **one** withLLMSessionForLlm session around every document batch. The session receives `options?.maxDurationMs ?? DEFAULT_EMBED_MAX_DURATION_MS`. The timer covers chunking and embedding across the whole call, not one memory batch. Earlier registration/update time is outside this timer; the observed 31m39s total is consistent with this mechanism.
- `dist/store.js:1638–1642, 1746–1767`: maxDocsPerBatch and maxBatchBytes only group the selected documents into memory batches. They do not limit the total selected work, renew the session, or return a continuation boundary.
- `dist/store.js:1913–1919, 1954–1962`: invalid sessions skip remaining document batches or chunks, emitting the exact warnings retained by Terra.
- `dist/llm.js:1542–1548, 1553–1557, 1577–1599`: the duration timer aborts the session controller; later operations reject an invalid session. embed/embedBatch do not pass that signal to the underlying embedding method. An already running native embedding operation is not interrupted by this timer.
- `dist/store.d.ts:412–431`: internal EmbedOptions declares maxDurationMs, explicitly documents the whole-session cap and that values <= 0 disable it. It does not declare an external AbortSignal for generateEmbeddings.
- `dist/index.d.ts:227–236`: the public QMDStore.embed options omit maxDurationMs and AbortSignal. They expose collection, force, model, memory batch limits, chunk strategy, and onProgress only.
- `dist/index.js:251–261`: the public wrapper constructs a new options object and **does not forward maxDurationMs**. A type assertion or extra JavaScript property cannot repair this omission.
- `package.json:8–15`: the package exports only its root. Deep-importing generateEmbeddings/LLMSession or reaching through the exposed internal store would bypass the supported public SDK boundary required for this task.

The cause is a whole-build SDK session deadline, not insufficient per-batch memory limits. There is no supported public lifetime option in this pin and no public pending-document selector or per-call work limit. Repeating embed until it stops failing would silently retry actual errors as well as timeouts. Artificial temporary collections or progressive mutation of indexed Markdown would introduce a new collection lifecycle and repeated scans, vector relocation, cancellation, and metric concerns; that is not a small embedding helper under the current one-collection architecture.

## Required dependency proposal, before implementation

The smallest change is to expose and forward the existing maxDurationMs through the **public** QMDStore.embed type and wrapper. Use a validated finite positive embedding-specific duration; do not disable the session deadline or increase QA/model budgets. That resolves the known 30-minute ceiling only for builds completing within the chosen duration. A safe duration cannot be established from the incomplete run; extending it alone neither guarantees full-corpus completion nor makes native inference cancellable.

For sustained builds, the recommended dependency-level change is public bounded embedding calls: a work limit distinct from maxDocsPerBatch/maxBatchBytes, a fresh finite session per call, a public signal, and an explicit result distinguishing successful bounded completion, remaining work, deadline exhaustion, cancellation, and embedding failure. Document limits must apply before session work selection. Cancellation should be observed during tokenization, before new native work, and between native batches; if native inference cannot be interrupted, that limitation must be explicit. Hard wall-clock cancellation requires a separately owned worker/process with shutdown/reaping semantics rather than Promise.race around live in-process work.

Report exact missing capability to the parent before any dependency edits: this pin cannot forward a lifetime override, externally cancel a session, or select a bounded amount of pending embedding work through its supported root SDK. A dependency patch/new immutable commit and integration changes require scope beyond this worker's write ownership. No such changes were made. Coordinate a new pin, installed artifact identity, build settings/revision, and final integrated build with the parent/other owner; do not patch node_modules. A pin/dist hash change must invalidate vector seeding conservatively under the existing settings contract. Do not change embeddingRevision or settings in this worker's scope.

After that API exists, keep CLEC's policy in one cohesive ingestion helper: call bounded public embed with force:false and regex chunking, check cancellation before/after each call, stop immediately on deadline/cancellation/nonzero errors/failures, and continue only after an explicitly successful bounded result reports remaining work. Require measurable forward progress and a finite total deadline/call bound. No lexical fallback or acceptance of partial vectors. Unchanged seeded builds must remain a zero-inference path.

## Metrics and coverage requirements

No current API or metric semantics were changed. Existing qmd.update.vectorsCopied measures vectors copied during collection relocation; embed.chunksCopied measures copies during embed itself. Do not rename or sum them as newly embedded work. `dist/store.js:1804–1809, 2034–2042` sets docsProcessed from the initial pending-document count, even if later batches are skipped: it is **not proof that every selected document completed**. Chunk counts count stored work after partial-document removal. The current SDK also performs its own bounded chunk retries (`dist/store.js:1822–1908`); CLEC must not add silent call-level retries.

With a bounded SDK, define docsProcessed as completed unique content documents per successful disjoint selection, aggregate actual successful chunksEmbedded/chunksCopied exactly once, and use elapsed wall time for whole-helper duration. Do not sum pending totals, progress snapshots, or overlapping attempts. Preserve failure details privately without leaking source text/path diagnostics to public errors. Keep compatible persisted metrics or coordinate an explicit schema change with the generation owner.

Successful embedding additionally needs an independent public coverage gate. The public getIndexHealth/getStatus methods use the configured embedding model (`dist/store.js:2061–2062`); getHashesNeedingEmbedding checks current model/fingerprint and expected chunk counts over active hashes (`dist/store.js:2215–2240`). With exactly one active destination collection, require needsEmbedding === 0, expected active document count, vector index presence, and existing metadata/collection validation before completion/publication. Collection/metadata counts and zero errors alone do not prove vector completeness: outer session expiration can skip entire later batches without recording those documents as chunk failures. The current buildQmd only checks embed.errors, collection relocation, and typed metadata; its observed failure was correctly rejected, but that does not establish rejection of every timeout shape. Final validation must also establish destination partition coverage through the supported dependency contract, rather than infer it from a global hash count alone.

Cleanup must preserve the primary embedding/cancellation/validation error if close/disposal also fails. Current `buildQmd` finally awaits qmd.close unconditionally and backup cleanup similarly closes in finally; either can mask an earlier error. When implementation resumes, explicitly retain primary errors and propagate cleanup errors only when no primary operation failed. Never publish until cleanup and complete-generation validation succeed. No standalone cleanup-only source patch was applied while the central fix is blocked.
