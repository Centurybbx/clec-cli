# QA boundary revision — parent design decision

2026-11-10. Design only, not implemented or runtime-validated. Based on the current `qa/service.ts`, `qa/pi.ts`, `qa/resources.ts`, the retained real answers and `qa-failure-investigation-20261110.md`. Implementation remains Sol medium; all tests remain Terra medium genuine E2E. Do not alter the frozen artifacts used by the active hybrid validator. Merge its findings into the implementation brief before lifting that freeze.

## Problem and intended behavior

The current model produces both a status and a free-form answer with citation markers. The host rejects a cited insufficient answer, even when the citation merely explains why related material does not answer the question. It also accepts unrelated valid citations elsewhere in an answer containing unread navigation facts. Raw model-facing source and passage identifiers look identical and have caused three read failures. Repeating existing prompt rules cannot resolve these interface problems.

Separate current-run read handles, evidence identities and answer rendering. Keep the existing search adapter, original reader authority, budget boundaries and shared CLI/API service. Do not add another model, verification agent, automatic retry, permissive JSON repair or hidden source-ID conversion.

## Model-facing evidence contract

`qa/evidence-context.ts` owns one registry for one run. Initial and supplementary search results register actionable handles mapped to authorized passage IDs. Handles must contain a per-run namespace: resetting to plain R1/C1 each turn allows an old handle to accidentally match a current one. The namespace need not be secret, but must differ across runs. Source IDs, version IDs and section IDs remain host metadata, not competing tool arguments.

Each navigation projection includes its read handle, descriptive title/date/date basis/source type, and the existing navigation preview clearly classified as unread. Each original-read projection includes its current-run evidence handle, provenance metadata, full admitted original text and scope. Deduplicate identical projections without removing original context. The registry explicitly lists issued evidence handles and remaining read/search budgets. A fresh turn cannot authorize a historical handle just because its ordinal matches.

`read_evidence` accepts only `{readLocator, expansion}`. Resolve the handle through this registry, then pass the mapped passage ID to the unchanged reader allowlist. Unknown/stale handles fail closed. READ_TOO_LARGE retains the existing narrower-scope recovery; do not convert other failures into fabricated evidence. Search and read progress events may retain their existing public DTOs; the model-facing projection is a separate concern.

## Structured answer and status

Replace the model-authored status/free-text-marker pair with exactly `{blocks: [...]}`. Each block is one of:

- `{kind: "answer", text, evidenceIds}`: a requested answer portion supported by current original reads; at least one issued evidence ID.
- `{kind: "context", text, evidenceIds}`: relevant source information that does not itself answer the request; at least one issued evidence ID. This permits a cited explanation of what related evidence actually says without pretending the question was answered.
- `{kind: "gap", text}`: an explicit unanswered part, uncertainty or request for clarification. No factual workaround, corpus-wide absence claim or invented provenance may be placed here.

The host derives the public outcome directly from this declared contract: any answer block plus a gap gives `partial`; answer blocks without gaps give `supported`; no answer blocks requires at least one gap and gives `insufficient_evidence`. Context blocks do not promote answerability. An insufficient result may therefore include valid contextual citations. This is a deliberate documented contract change, not post-hoc repair of an inconsistent model status. The no-candidate host path stays `no_hits` with no model call.

The central `qa/answer-contract.ts` parses and validates exact discriminated fields, nonempty text, bounded block/total output size within the existing output budget, and current issued evidence IDs. Reject malformed JSON, unknown fields/IDs and model-authored citation markers. It returns typed blocks and a derived outcome. The host renders plain text and stable public C markers from those blocks, then reconciles every emitted citation with original text/version/generation through the reader. Public C ordinals may reset because they are never accepted as model read/evidence handles. Apply the same rendered contract in session validation and CLI/API results; eliminate divergent marker rules.

### Storage and transport consequences confirmed by source review

`sessions/validation.ts` currently independently rejects every `noEvidence` result with citations; changing QA alone would therefore fail at persistence. Remove the redundant `noEvidence` boolean from the new result and CLI completion contracts, and use `answerability` as the single outcome discriminant. Update HTTP DTOs, CLI mapping, types and documentation together. No compatibility shim is required. `no_hits` still requires zero reads/citations; `insufficient_evidence` permits contextual citations but no answer blocks; `supported`/`partial` require answer blocks and their citations.

Persist normalized host blocks alongside rendered text and citations so the session boundary can validate outcome/block consistency without guessing roles from prose. Normalized blocks carry public read-issued citation IDs, never model-facing action handles. Store validation checks block shape, derived outcome, deterministic rendered text, marker/list equality and exact identity against that run's recorded reads. Keep one dependency-neutral answer contract/rendering module shared by QA and session validation; session code must not import the Pi adapter or initialize model/runtime code. Its location may be `domain/answer.ts` rather than `qa/answer-contract.ts` if that keeps layering clean.

Do not renumber reader-issued C IDs when rendering. `sameCitation` requires final citations to match previously emitted read citations, including ID. Map each run-scoped model evidence handle back to its existing reader-issued C ID; a final answer using only C3 may retain C3. A dense display sequence is less important than stable event/result identity.

Version the incompatible persisted result contract and reject old session state with a clear startup diagnostic; use new isolated state for acceptance. Do not overwrite/delete previous session evidence, frozen test states or originals. Inventory all consumers of the removed boolean before building. The E2E harness must be updated by Terra, not the implementation owner, and old raw evidence remains unchanged. Add a real insufficient-with-context case through both CLI and HTTP, persisted GET and SSE replay, then restart to verify the same result remains valid.

Preserve provenance limitations supplied by source metadata, but do not let the model infer transcript completeness or verbatim status from narrative format. Prefer a host-rendered source-quality note based on explicit metadata over asking the model to improvise these caveats. Such notes are distinct from model answerability and must retain source association.

Block structure ensures each declared factual block identifies evidence; it does not prove that the evidence entails the text or that all requested parts were answered. A model can still misclassify a claim as a gap, omit a condition or cite an unrelated original. Real claim-by-claim grading remains mandatory, especially full CLEC-009 and conditional questions. Do not claim semantic verification from `validated: true`; document its structural/source-integrity meaning.

## Diagnostics and lifecycle observation

Use an injected finite-code diagnostic sink with a bounded local JSONL implementation. Compose it once and pass it to QA, model admission and scheduler; no module-global singleton. Record run ID, stage, reason code, sequence/time and numeric counts. Record first failure separately from cleanup errors. Never serialize arbitrary exceptions, prompts, answers, source contents, headers, credentials or provider payloads.

Record model admission before invoking the SDK stream and first actual provider stream activity separately. Admission proves a local decision, not remote execution or billing. A safe first-activity event permits Terra to trigger real cancellation/crash after observable provider activity without a proxy, mock or injected delay. If the SDK exposes no appropriate event, report the limit rather than inventing the observation. End/abort/settlement events must distinguish lifecycle ordering from usage completeness.

Include refused requested admission units and content-free component sizes. Keep current cumulative admission, request/output/read/search limits. Do not increase budgets or truncate original text/history to hide case 033. Diagnostic failures must not leak content or mask the original QA failure; define bounded sink failure behavior explicitly in the implementation handoff.

## Independent review disposition — 2026-11-11

Parent read `qa-contract-review-20261110.md` and accepts its seven findings. These decisions resolve the implementation ambiguities above:

1. **Host empty search:** the persisted result has an explicit host-only `no_hits` variant with `blocks: []`, canonical host gap text, empty citations, successful empty retrieval and zero reads/model admissions. Model block derivation never produces this variant. Keep scheduler enforcement of no nonempty search results and enforce zero model-call counters; the QA path itself supplies the causal guarantee by returning before Pi execution. A nonempty retrieval with oversized unread sections is not no_hits.
2. **Observation semantics:** preserve existing SDK option callbacks and use supported public response/provider-event hooks. Record request ordinal, admission, HTTP response, first actual provider event, stream end/abort and local settlement separately. Record only the first activity per request, without event content. Terra must show the observation preceded cancellation/crash and distinguish an already-ended stream race. A response or observed chunk does not prove remote work is still active, remote cancellation or complete billing. Optional callback support must be demonstrated in real execution; normalized text/tool deltas may be used only with an explicitly weaker label.
3. **Host notes:** derive notes deterministically from final retained citation metadata only, through an explicit recognized-quality mapping. Render in first-citation/source order and deduplicate by source/version and note kind. Persist citations as note inputs; do not append untracked prose or alter outcome. Unknown quality produces no inferred assertion. No completeness, verbatim, speaker-verification or source-type claim beyond explicit available metadata. This needs no ingestion change or extra note model field.
4. **Independent structural bounds:** retain provider maxTokens 2048 and successful-stop requirement. Parser bounds are separately named: at most 65,536 raw UTF-8 JSON bytes, 16 blocks, 4,096 UTF-16 units per block, 16,384 total model text units and 64 evidence-reference occurrences in total. These are resource bounds, not token estimates. Validate references before rendering; host markers and recognized notes add bounded deterministic output. Reject truncation/malformed output; no repair or cap increase to pass a case.
5. **Durability scope:** normalized blocks are public on run results/terminal SSE and persisted with the result. History messages remain text/citations derived from the same render. Validate at the pre-commit boundary against recorded reads; GET/replay/restart acceptance establishes faithful durable round-trip, not fresh entailment or a new whole-database validation scan. Keep schema gating and do not claim post-restart revalidation that is not implemented. New state and Pi directory must both be isolated from prior evidence.
6. **History and identity:** keep completed Pi history. Deduplicate read projections by exact generation/version/section/span identity; repeat reads reuse one current handle. Do not expose host C IDs as an alternative model citation vocabulary. Fresh handles enforce authorization only; semantic reuse of historical statements still needs manual evaluation. One block should express one answer portion with its conditions, but mechanical atomicity is not claimed.
7. **Diagnostic sink:** use a simple nonthrowing bounded synchronous local append sink, avoiding a separate queue/journal. Cap records at 4 KiB, active file at 4 MiB and retain two rotated files. Serialize only allowlisted fields; assign process-local monotonic sequence plus run/request identity and timestamp. First provider activity only, never per-delta logging. Successful append means observable to the local reader, not fsync/crash durability. On write/rotation failure, suppress the sink exception and issue a single content-free stderr warning plus an in-memory drop count; do not fail QA. Preserve the primary application error across cleanup, record cleanup failures separately, and use the cleanup error only when no primary failure exists. Share injection/composition across CLI and HTTP, without a singleton.

No new dependency or provider feature is required for these decisions. Implementation scope remains the three boundaries and their consumers described above. Retain all existing search/read/model limits, scheduler settlement leases and host/Pi orphan reconciliation. The independent review is static evidence only; no item here is a runtime pass.

## Final-output publication boundary — source review follow-up

Source review on 2026-11-11 found that `qa/service.ts` emits final text/citation progress before returning, while `sessions/scheduler.ts` validates the returned answer afterwards. `sessions/store.ts` persists text progress as a partial assistant message immediately. Thus pre-commit validation alone does not prevent a rejected result from leaving answer-shaped progress/history. This is a source-level ordering finding, not a reproduced runtime failure.

As part of the same result-contract revision, make the shared QA service return its fully validated answer and emit only search/read progress while executing. The stateless CLI adapter renders text/citation/completion events from that returned result after successful service cleanup. The session executor likewise returns the result; it must not independently publish final answer text. Narrow the executor progress type accordingly, rather than accepting and silently dropping answer events.

After scheduler validation and its active-run check, the store completion transaction writes the final assistant message, result, ordered final text/citation events and completed terminal event together. Publish the committed events to live subscribers only after transaction success. Retain the existing event shapes for consumers; final text remains buffered, not provider-token streaming. Search/read events and cancellation/timeout behavior remain live. A rejected or cancelled run may retain search/read evidence but must not gain a final answer message or answer text/citation events. No separate partial-answer buffering mechanism is needed because this product does not stream unvalidated answer tokens.

Keep Pi reconciliation anchored to host-completed runs: a Pi-side commit entry alone does not authorize replay of a turn whose host completion transaction failed. This change must preserve existing orphan exclusion and settlement leases, not attempt a cross-database transaction with Pi files. Update session/HTTP documentation and the Terra handoff to verify successful final event ordering, durable SSE replay and history/result agreement, plus the absence of final answer output on genuinely observed failed/cancelled runs. No mocks or injected provider failures are authorized.
