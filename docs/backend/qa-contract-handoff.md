## Model, public result and publication contract

Model answer/context: exactly `{kind:"answer"|"context",text,evidenceIds:[issued current E handles]}`. Gap: exactly `{kind:"gap",text}`. Nonempty text, no model-authored C/numeric/E/R citation markers, no extra keys or unknown IDs. Each supported block should retain one requested portion with all its conditions; gaps cannot hide factual assertions, corpus-wide absence or invented provenance. These semantic instructions are not mechanical proof.

Independent limits: 65536 raw UTF-8 JSON bytes; 16 blocks; 4096 UTF-16 units/block; 16384 total model text units; 64 evidence-reference occurrences. Provider maxTokens stays 2048 and successful complete stop remains mandatory. No truncation/repair/retry. Host markers and recognized quality notes add bounded deterministic output. Fixed budgets stay two searches (one directed supplementary), eight total read attempts including refusals, 40000 original UTF-16 units, nine tool attempts, four admitted model requests, full serialized context UTF-8 bytes +2048 reserve/request, default cumulative admission 240000. No history/original truncation or budget inflation to hide 033.

Public result is `{validated:true,answerability,blocks,text,citations,metrics}`; `noEvidence` and CLI `answerStatus` are removed without compatibility shims. Public block `evidenceIds` are stable reader C IDs, never accepted as model action/evidence handles. Answer plus gap → partial; answer without gap → supported; no answer requires a gap → insufficient_evidence, with optional cited context. Context never promotes answerability. Host-only no_hits has `blocks:[]`, canonical NO_HITS_TEXT, no candidates/reads/citations/model calls or attempts. Scheduler requires an observed empty successful search and zero no-call/read/admission counters. Oversized unread related sections are not no_hits.

Recognized source-quality notes derive only from final retained citation quality metadata, in first-citation order, deduplicated by source/version/note kind. The mapping lives in domain/answer.ts. Unknown labels produce no note. No completeness/verbatim/speaker-verification or source-type inference is made beyond the explicit recognized metadata. Notes are re-rendered from persisted citations, not independent untracked prose, and do not change answerability.

Session precommit checks exact citation equality with recorded reads (including stable C ID, generation/version, source/section, range, quote and provenance), public block validity, derived outcome, ordered used citation IDs and exact deterministic text. It checks active/deadline again immediately before the synchronous completion transaction. That transaction writes assistant history, result, one text event, ordered citation events and completed terminal event together. Scheduler publishes only returned committed envelopes. Cancellation/failure may retain search/read/metrics but must have no final text/citation events or final assistant message. Text stays buffered; no new partial-token machinery.

Result blocks are public via HTTP GET and terminal SSE and persisted in result snapshots; history remains text/citations from the same render. GET/replay/restart establish faithful durable round-trip of precommit validation, not a new source/semantic scan. `validated:true` means structural and original-source integrity only. Related valid evidence may still fail entailment; model labels may omit requested conditions or hide facts in a gap. Manual claim-by-claim grading remains required.

Session schema is 3. Schema checks reject old state before owner recovery; no migration/deletion/overwrite. Use both a fresh CLEC_STATE_DIR and fresh CLEC_PI_DIR, especially when the latter was externally configured. Pi committed marker alone is insufficient: unchanged openConversation reconciliation requires host-completed run membership, branches before an orphan suffix, preserves old branches and does no automatic paid replay. Postterminal session/global leases remain held until executor cleanup/settlement. There is no cross-database transaction with Pi files.

## Diagnostic contract and evidence semantics

`CLEC_DIAGNOSTIC_PATH` defaults to `CLEC_STATE_DIR/diagnostics.jsonl`. Synchronous nonthrowing append, 4 KiB maximum serialized record, 4 MiB active file, two retained rotated files (`.1`, `.2`), no queue/journal. New directories/files use 0700/0600. Sequence is monotonic within the process's composed sink, with timestamp, generated run ID, optional request ordinal and allowlisted counts. Successful append makes the line locally observable; it is not fsync/crash durability. Separate CLI/API processes have independent sequences.

Only finite stages/codes/reasons and named nonnegative numeric counts are serialized. No prompt/answer/source/payload/header/credential/raw error/stack, arbitrary code or exception message. Unknown errors map to UNKNOWN. Write/rotation/record failure increments the in-memory `dropped` count and emits at most one fixed content-free stderr warning per sink; diagnostics never fail QA. Dependency-injected implementations must uphold the nonthrowing interface contract. First application failures are recorded before unwinding; CLEANUP_FAILURE records are separate. Pi and evidence cleanup attempt all operations and preserve the original rejection; a cleanup error becomes authoritative only when no primary failure exists.

Finite stages: qa, admission, provider, scheduler, cleanup, http, cli. Codes: BEGIN, SUCCESS, FAILURE, CLEANUP_FAILURE, ADMITTED, REFUSED, HTTP_RESPONSE, FIRST_PROVIDER_EVENT, ABORT_REQUESTED, STREAM_END, STREAM_ABORT, LOCAL_SETTLED, CANCELLED, TIMED_OUT, COMMITTED. Finite reason enum is in diagnostics/contracts.ts. Admission records requestedUnits, contextBytes, systemBytes, messageBytes, toolBytes, outputReserve, prior reservedUnits, limitUnits and admitted modelCalls, including on refusal. Component sizes are serialized measurements, not additive token estimates; full context size remains authoritative.
