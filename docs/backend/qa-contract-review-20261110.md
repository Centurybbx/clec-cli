# Independent static review of the proposed QA contract

Reviewed 2026-11-11 against `qa-contract-decision.md` dated 2026-11-10. This is a design review, not implementation approval or runtime acceptance. No children, tests, build, install, application execution, provider requests, credential access, held-out data, or raw runtime logs were used. Only this report was written. The frozen inventory was read for its identity and scope; its 240 files were not rehashed in this review.

The boundary refactor is justified. A run-scoped projection registry, a small dependency-neutral answer module, and injected bounded diagnostics fit the existing architecture without rewriting retrieval, the original reader, or session scheduling. Resolve the following contract details before handing implementation to Sol medium. Priorities describe implementation risk; none of the unimplemented proposals below is presented as a reproduced production failure.

## Findings, in priority order

### 1. P1 — Define a host-only `no_hits` variant before sharing outcome derivation

**Observed contract contradiction / implementation gap.** `docs/backend/qa-contract-decision.md:27` derives `insufficient_evidence` whenever there are no answer blocks and at least one gap, but also preserves `no_hits`. Lines 35 and 33 require session validation of derived outcome and normalized blocks, without defining the exception. A host-generated gap passed through that derivation becomes insufficient; an empty block list violates the model contract. This is not a reason to remove `no_hits` or let the model choose it.

Current host behavior is explicit at `backend/src/qa/service.ts:82–83`. Independent invariants are split between `backend/src/sessions/validation.ts:66` (zero reads) and `backend/src/sessions/scheduler.ts:173–175,199–200` (no nonempty search result). Zero reads alone is not evidence of an empty retrieval: oversized prefetches can leave a nonempty search with no originals (`backend/src/qa/service.ts:92–103`).

**Correction:** Give the host result a documented `no_hits` branch with canonical host text, no blocks or a precisely specified host gap representation, no citations/reads, successful empty retrieval, and zero model admissions. Derive the other three outcomes exclusively from model blocks. Keep the nonempty-search guard in the scheduler and add no second retrieval implementation to the pure renderer. Explicitly decide whether model metrics are an enforced no-call invariant or only an attestation. This is a small discriminated-result exception, not another answer pipeline.

### 2. P1 — Provider activity can be observed, but event receipt cannot guarantee an active request at cancellation

**Observed SDK surface; unsupported timing guarantee if read literally.** `docs/backend/qa-contract-decision.md:49,59` proposes triggering cancellation/crash after first actual provider activity. The installed public definitions offer:

- `backend/node_modules/@earendil-works/pi-ai/dist/types.d.ts:107–118`: `onResponse` after HTTP response and before body consumption; `onProviderStreamEvent` for parsed provider events, explicitly conditional on adapter support.
- The same file at lines 240–242: `SimpleStreamOptions` inherits these options. `dist/api/openai-completions.d.ts:5,23–24` declares the installed completions stream surfaces using them.
- `backend/node_modules/@earendil-works/pi-agent-core/dist/types.d.ts:475–478` and `pi-coding-agent/dist/core/agent-session.d.ts:49–51`: session listeners can receive normalized assistant stream updates. `pi-ai/dist/types.d.ts:577–590` specifies normalized ordering, not the network provenance of `start`.

These declarations establish a feasible public hook, not that this installed adapter invokes every optional callback, or that remote computation/billing remains active when Terra reacts. `onPayload`, admission, `agent_start`, `turn_start`, and a generic normalized start are not sufficient remote-execution observations. Existing code observes admission and final usage only (`backend/src/qa/pi.ts:93–109`); lifecycle report lines 19–25 correctly leave provider-observed cancel/crash unaccepted.

**Correction:** Inject content-free observation into the existing stream-options wrapper, preserving prior callbacks. Distinguish request ordinal, admitted, HTTP response received, first parsed provider event observed, stream end/abort, and local settlement. Do not inspect/store headers or payload content. Prefer the explicit provider-event observer; `onResponse` proves a response, not a streamed generation chunk. A normalized nonempty text/tool delta is a possible weaker fallback whose meaning must be named accurately. Adapter invocation and event ordering remain Terra real-E2E questions. An event followed by a crash proves that order; a fast completion race must remain inconclusive for cancellation during local unsettled streaming. Neither the hook nor a crash proves remote cancellation or billing completeness. No stream proxy, delay, SDK patch, or second agent is needed.

### 3. P2 — Source-quality notes need a normalized representation and explicit metadata rules

**Observed design gap, not a demonstrated rendering defect.** The proposal requires deterministic rendering from persisted blocks (`docs/backend/qa-contract-decision.md:35`) while preferring separate host-rendered source-quality notes with source association (line 41). Model blocks permit only answer/context with evidence IDs or gap without evidence IDs (lines 21–25). There is no representation for those host notes. Appending ad hoc prose breaks deterministic text equality; forcing a note into an answer block promotes answerability incorrectly; an unassociated gap loses provenance.

`backend/src/domain/contracts.ts:3–10,32–37` has free-form `quality`, source `type`, and optional date/date basis; a read citation does not carry source type or an explicit completeness/verbatim flag. `backend/src/ingestion/manifest.ts:17–28` accepts arbitrary nonempty quality strings. Actual catalogue labels are more limited than universal completeness claims: `backend/src/catalog/adapters.ts:62,76,118,149` describe probable ASR, unverified speakers/timestamps, possibly mixed page content, and third-party curated interpretation. They do not establish that every transcript is incomplete, or any transcript is a verified verbatim recording.

**Correction:** Use a small host-owned note collection keyed to retained citation/source identity, or a deterministic pure note function of explicitly supplied canonical metadata. Define note ordering/deduplication and whether notes participate in result text. Include that input in persistence and the shared renderer if it affects text. Use an explicit mapping for recognized metadata, preserving uncertainty for unknown labels; never infer completeness or verbatim status from source type, narrative form, or the absence of a warning. Avoid an ingestion/schema redesign just to generate richer caveats.

### 4. P2 — A token cap is not the answer parser's byte/character cap

**Observed unit mismatch risk in the brief.** `docs/backend/qa-contract-decision.md:29` asks for bounded block/total output size “within the existing output budget” without specifying units or whether JSON overhead and host rendering count. Current provider output is capped at `maxTokens: 2048` (`backend/src/qa/pi.ts:97–98`); admission reserves serialized UTF-8 bytes plus 2048 conservative units (`backend/src/qa/budget.ts:4,11–18`). These are deliberately different concepts. The parser cannot establish a 2048-token limit by comparing JS string length or UTF-8 bytes to 2048. Blocks, handles, and JSON escaping also consume provider output capacity.

**Correction:** Retain provider `maxTokens`, cumulative admission accounting and the existing complete-stop requirement (`backend/src/qa/pi.ts:122–123`). Separately specify finite raw-JSON bytes, block count, per-block/total text length, and evidence-reference count, with named units. Deterministic rendering may add bounded markers/notes outside model text; account for that explicitly. Reject length-truncated or malformed outputs rather than repairing them. Do not claim the new contract will eliminate malformed JSON or long-context 033, and do not enlarge limits to fit it. A tokenizer dependency is unnecessary for structural size bounds.

### 5. P2 — Persisting blocks does not make replay or restart a validation boundary

**Observed code behavior; proposed acceptance wording needs precision.** Current live result validation runs in `backend/src/sessions/scheduler.ts:197–201`. Persisted run results, messages and event payloads are subsequently JSON-parsed/cast without that validation (`backend/src/sessions/store.ts:162–170,189–206`). Startup checks schema and recovers pending runs, not completed-answer structure (`backend/src/sessions/store.ts:41–45,82–99`). HTTP GET and terminal SSE use a hand-written result mapper (`backend/src/http/dto.ts:21–25,30–38,56–65`); replay calls that mapper (`backend/src/http/sse.ts:52–56`). Merely adding blocks to `ValidatedAnswer` does not expose them through these DTOs or revalidate them after restart.

**Correction:** State whether blocks are public or internal. Persist them at least in `runs.result_json` and terminal result snapshots; derive messages from the same validated rendering rather than maintaining a second block authority. If public, include them explicitly in the HTTP result allowlist and describe history endpoints that return text/citations only. If the requirement is restart revalidation, reconstruct that run's recorded reads and invoke the pure stored-result validator on the relevant loading boundary; do not claim GET/replay alone does so. Otherwise scope the acceptance claim to faithful durable round-trip of a result validated before commit. No whole-database semantic scan or original-store access from the renderer is necessary.

### 6. P2 — Fresh handles reject stale authorization; they do not remove historical evidence or cross-turn semantic reuse

**Residual risk, already partly acknowledged by the proposal; not an observed restore defect.** `docs/backend/qa-contract-decision.md:13–17,37` correctly separates fresh model evidence handles from reader-issued C IDs. However, completed Pi context intentionally remains in the session (`backend/src/qa/conversation.ts:17–49`; `backend/src/qa/pi.ts:114–117`). Fresh handles cannot stop a model copying a previous factual statement and attaching an unrelated current valid handle. Outcome derivation also trusts whether the model labels a block answer, context or gap. A multi-claim answer block with one unrelated citation still passes structural checks. This is not semantic verification, as decision line 43 already states.

**Correction:** Preserve completed history and make current handles unambiguous; do not rewrite old tool messages, alias old handles, or purge history to make the test pass. Ensure the model-facing original-read projection does not accidentally expose a second actionable citation vocabulary: C IDs remain host-side identities while model `evidenceIds` accept only fresh handles. Deduplicate by exact read identity (generation/version/section/span), not identical text across distinct sources, and keep the same handle on repeated reads in one run. Include old-handle rejection and prior-claim/current-unrelated-evidence assessment in Terra's bounded real follow-ups. Prompts should request one supported answer portion per block with its conditions, without claiming mechanically enforced atomicity or coverage. Context with no answer plus an explicit gap is legitimately insufficient even with contextual citations; do not restore the old no-citation rule.

### 7. P2 — Specify diagnostic failure and durability behavior before treating it as an acceptance signal

**Open design requirement, not evidence of a new runtime failure.** `docs/backend/qa-contract-decision.md:47–51` appropriately requires injection, bounded records and separate primary/cleanup failures, but delegates sink failure policy to the handoff. A queued JSONL write can vanish at SIGKILL; an awaited write can throw or delay an SDK callback; per-delta recording can defeat a nominally bounded queue. Existing nested cleanup can replace a prior rejection (`backend/src/qa/pi.ts:133–146`; `backend/src/qa/service.ts:109–111`). Catching only the scheduler's ultimate exception (`backend/src/sessions/scheduler.ts:202–205`) cannot recover the original cause.

**Correction:** Define fixed record size, queue/file/rotation bounds, first-event-per-request emission, sequence semantics, flush/visibility semantics and a nonthrowing, content-free failure/drop indicator. Choose whether a record's visibility is sufficient for Terra to act, without asserting crash durability for unwritten records. Capture the first failure where it occurs before cleanup; record cleanup failures separately. Define which error remains authoritative if both fail. Do not make diagnostics a required public SSE stage or let a full disk turn an otherwise valid answer into a new failure. Compose the same sink for stateless CLI and HTTP service paths (`backend/src/cli.ts:64–66`; `backend/src/app/index.ts:8–23`), with no global singleton.

## Decisions that should remain intact

- **Reader-issued citation identity is correct.** `backend/src/evidence/reader.ts:42–49` reuses a citation per section and assigns IDs on first read. `backend/src/sessions/validation.ts:43–47,56–62` and `sessions/scheduler.ts:180–192` compare the full identity including ID. Render a used C3 as C3, even if C1/C2 are unused. Deduplicate final citations by first rendered use and reconcile against originals through the reader (`evidence/reader.ts:61–63`). No dense renumbering or copied/reconstructed quotes.
- **Removing `noEvidence` is justified.** Current QA rejects cited insufficient output at `qa/service.ts:106–107`, and sessions independently reject it at `sessions/validation.ts:64–65`. The new insufficient-with-context rule must change both. Direct product consumers found: `domain/contracts.ts:44`, `sessions/types.ts:37–41`, `sessions/validation.ts:49–66`, `qa/service.ts:72–75,123–124`, and `http/dto.ts:21–25`. Use the same four-value `answerability` in stateless CLI completion instead of retaining the three-value `answerStatus` translation. Session CLI forwards HTTP result/events and returns history (`app/session-cli.ts:23,46,51–53`). Update active contracts/http/integration/sessions/handoff docs; preserve historical evaluation reports and raw evidence.
- **One session schema bump suffices.** Replace schema 2 checks/creation/insertion consistently (`sessions/store.ts:44,48,84–85`) and reject old state before ownership recovery. Do not add a compatibility migration, change evidence generations, or rewrite old Pi files. Isolation must include the configured Pi directory: `config.ts:32` permits `CLEC_PI_DIR` to point outside the fresh state root.
- **Keep existing orphan reconciliation.** Host completed-run membership is checked in addition to Pi's commit marker (`qa/conversation.ts:35–48`). A Pi commit appended before host completion (`qa/service.ts:79`; `sessions/scheduler.ts:197–201`) does not by itself authorize restoration after failure/crash. Preserve branch-before-first-uncommitted-run behavior and append-only retained evidence; audit it with genuine crash/restart traces rather than adding another journal. Lifecycle report lines 23–25 do not establish a full history audit or orphan-exclusion pass.
- **Use a pure shared answer module.** It should validate discriminated block fields, normalize evidence references, derive declared outcome and render deterministically. QA resolves fresh handles and asks the reader to validate original identities; sessions compare persisted references to recorded read events. The pure module must not import Pi, SQLite, evidence storage, or initialize runtime services. Keep source projection and SDK tool adaptation separate. Model-authored markers should be rejected in model text; original excerpt content must remain unchanged even if it contains bracket-like text.

## Bounded implementation handoff

After the active hybrid validator returns and the parent lifts the freeze, one Sol medium owner can implement three small boundaries: (1) run evidence projections/registries in QA, (2) pure domain answer contract/rendering with the host-only empty-search branch and explicit host-note inputs, and (3) finite diagnostic contracts plus a bounded I/O sink. Wire them through the existing Pi adapter, QA composition, session validation/schema, DTOs and both CLI entry paths. Keep search, QMD, original storage/reader authority, admission amounts, history preservation and scheduler lease/settlement architecture intact. This scope needs no provider change, additional model, retry, JSON repair, new verifier, ingestion redesign, compatibility layer or dependency update.

All test authoring and execution remain Terra medium real E2E only, after a new complete frozen inventory. Include the parent regression cases, exact citation/event/result identity, contextual insufficient results through stateless CLI and durable HTTP/GET/SSE/restart, host-only no_hits with zero calls, two-turn fresh handles, conditions/provenance grading, and accurately classified provider-observed cancellation/crash plus orphan reconciliation. Preserve every attempt and keep races/unobserved branches inconclusive. Resolve the remaining scope and slot-release gates listed at lifecycle report lines 15,19–25; these are not all solved by answer-contract work. Full hybrid and independent held-out acceptance remain separate release gates; this reviewer accessed neither held-out inputs nor runtime evidence for new verification.
