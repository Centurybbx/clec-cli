## Interaction and diagnostic limits

The prompt already says navigation is not evidence, current IDs reset, preserve conditions, and return exact JSON (`qa/resources.ts:3–10`; `qa/pi.ts:114–117`). Merely repeating those rules is not a sufficient fix. Raw Candidate JSON exposes several indistinguishable 64-hex identifiers (`domain/contracts.ts:8–18,27–30`), while the read tool accepts another 64-hex string (`qa/pi.ts:75–81`). Actual source/passsage confusion is evidenced above. Previous completed Pi context is intentionally preserved (`qa/conversation.ts:17–49`); historical locator reuse is a plausible contributor to 004, not proof of a general restore defect.

Host prefetch reads only the top two candidates (`qa/service.ts:92–103`), whereas twelve navigation candidates are shown, including exact original previews (`search/qmd-http.ts:100–102`; `search/navigation.ts:8–22`). Full 009 demonstrates the resulting temptation to answer from an unread preview. Broad/ambiguous lexical ranking and optional rather than guaranteed gap reads are plausible contributors to semantic misses. They are not proven hybrid failures. Never solve this by reading the corpus eagerly or truncating original sections.

Public error sanitization is intentional: `sessions/scheduler.ts:202–205` drops the caught exception and emits RUN_FAILED except for selected SessionErrors. F/api.stdout and api.stderr are empty. Pi preserves some tool/model errors and outputs, but not the host validation exception, rejection stage, cleanup precedence, or rejected admission size. Therefore exact scheduler-caught errors, any masking cleanup failures, run-to-run frequency, hybrid impact, and full claim entailment remain unknown. No runtime reproduction was attempted.

## Modular implementation proposal — after parent lifts freeze

All implementation stays TypeScript/Sol, one Pi and official DeepSeek, QMD, existing evidence authority and originals. No development-answer hardcodes, extra agent, provider, automatic retry or larger budgets. The following boundary refactors make the change reviewable without rewriting search/storage.

1. **Internal diagnostics first.** Add `backend/src/domain/diagnostics.ts` with an injected `DiagnosticSink.record({runId,stage,code,reason,counts})` contract and finite allowlisted codes/reasons. Add a local bounded sink under `backend/src/io/diagnostics.ts`, composed in `app/index.ts`. Instrument service retrieval/prefetch/validation, Pi admission/tool/final parsing/cleanup, and scheduler catch. Record first failure and cleanup failures separately; retain metrics and settlement. Include issued/unknown citation IDs, locator classification, admitted/requested units and parser reason/offset, never prompts, answers, source text, headers, credentials, raw exceptions/stacks or provider bodies. Do not expand public DTOs/SSE/errors; diagnostics are operator-local with bounded records/rotation and restrictive permissions. Unknown errors get stage plus UNKNOWN_ERROR, not arbitrary `.message`.

2. **Explicit model evidence boundary.** Add `backend/src/qa/evidence-context.ts` owning a per-run locator registry and model-facing projections. Use opaque `readLocator` handles mapped only to currently returned passage IDs; distinguish descriptive source metadata from actionable handles. `qa/pi.ts` tool accepts `{readLocator, expansion}`; `qa/service.ts` registers both initial/supplementary results and resolves handles before the unchanged RunEvidenceReader allowlist. Preserve source provenance, exact original text, full admitted read scopes and original question/history through supported Pi APIs. Unknown/historical handles remain fail closed; never silently reinterpret a source ID as a passage or widen scope. Present issued citation IDs/remaining budgets explicitly, navigation separately. A visible relevant unread preview should lead to an authorized read or a gap, not reproduction of its facts.

3. **Central answer contract and rendering.** Extract parsing/validation from Pi into `backend/src/qa/answer-contract.ts`; share marker parsing with `evidence/reader.ts` and `sessions/validation.ts`. Prefer an explicit block contract: supported claim blocks `{text,citationIds}` and gap blocks, plus status. Require each claim's IDs to exist in the current read registry; host renders markers, rejects model-authored alternative citation syntax, extra fields, malformed JSON, unsupported status combinations and insufficient results with supported claim blocks. Keep original quote/version/range validation authoritative. Put prompts in `qa/resources.ts` around scenario/speaker/condition-preserving blocks and original reads. This closes structural loopholes but **does not prove entailment**: an unrelated valid citation can still be assigned to a claim. Semantic review of real outputs remains a release gate; do not advertise it as solved by schema/prompt alone. Provider-native structured-output support is not established here and must be verified before depending on it. No permissive JSON repair, dropping unknown IDs, automatic status promotion, citation substitution, or acceptance of unsupported claims.

4. **Measured context accounting.** Extend `qa/budget.ts` diagnostics with requested units and component sizes, without storing content. `evidence-context.ts` can avoid redundant model-facing metadata while retaining all admitted original context; do not delete history, shorten originals or change the admission formula to make 033 pass. A genuine exhausted budget remains a failed run with safe internal attribution. Any semantic guarantee beyond deterministic identity/structure checks needs a separate approved design, not a validator bypass.
