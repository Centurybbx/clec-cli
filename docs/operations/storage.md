# 源码与本地资料的存储边界

Git 基线保存本项目源码、采集脚本、依赖清单、锁文件、设计文档、评测用例及人工结果摘要。`collection/` 不是整体忽略目录，站点清单、来源记录、文件校验值和 ASR 的 `metadata.json` 仍可追踪。`collection/sources/clec-md/` 是外部仓库的采集快照，不属于本项目源码。

原始资料留在本地，包括根目录的公开资料 ZIP、解压目录和 PDF，以及 `collection/sources/` 的下载原件、`collection/web/` 的 HTML、正文与字幕、`collection/text/` 的提取文本。Git 忽略这些文件。来源清单能帮助校验和续采，但不能替代资料备份。原始资料以及被隔离的可疑转写应保留到有独立备份且人工确认用途之后。`collection/tmp/` 中待核听视频也不能仅凭临时目录名称删除。

依赖、下载模型、`index/`、`backend/dist/`、`backend/.data/`、缓存及运行日志是本地运行产物。依赖与索引可根据清单和源码重建。运行数据库可能含任务状态，清理前需要停止相关进程并确认是否要保留。`docs/backend/` 的原始验证产物留在本地，设计文档、候选补丁和人工结论仍可追踪。`.audit/` 用于本地操作记录，不进入源码基线。

私有 `.env`、凭证和私钥不进入 Git。`.env.example` 可追踪，示例内容仍需人工检查。忽略规则不扫描文件内容，也不会移除已经暂存或已提交的数据。

修改忽略规则只改变后续文件选择，不释放磁盘。Git 对象清理与原始数据归档需要独立核验。建立基线前可用 `git ls-files --others --exclude-standard` 检查候选文件，用 `git check-ignore -v <路径>` 核对某个文件的归属。

## 保留和清理新任务的运行产物

以下是新 CLEC 工作的操作规则。现有旧 backend 命令尚未自动强制这些规则，也没有自动配额或垃圾回收。运行任务的人负责检查和清理。

1. 将每个新任务的运行目录放在仓库外的 `~/.cache/clec/runs/<run-id>`。只读共享 canonical 数据。需要写入时，在运行目录中创建副本，同一时间最多运行一个 full-corpus 可写副本。
2. 启动前检查目标磁盘的可用空间，估算本次任务的增量占用，包括副本、索引、临时文件和日志。用 `df -h ~/.cache/clec/runs` 检查已创建的运行目录所在磁盘。扣除预计增量后，至少留出 5 GiB。无法估计增量时，不启动全量复制。
3. 在每个运行目录记录 owner 和 manifest。记录任务目的、进程或会话标识、输入路径与校验值、使用的 generation、可重建文件路径及重建命令。任务结束时更新状态，并保留小日志和结果摘要。
4. 清理前向 owner 确认任务已结束，检查相关进程和文件占用，并核对 manifest。确认副本不活跃、可以重建且没有仍需保留的任务状态后，再删除副本。不能只按文件年龄、目录名称或修改时间删除。
5. 保留一个当前完整 generation，供旧验收回查。更新时最多新增一个候选 generation。候选验收通过后，先更新引用，再检查旧 generation 是否仍被任务或验收资料引用。仍被引用的版本继续保留，不能在切换后立即删除。

## 预建 CLI 数据包

新 CLI 的消费端目录默认是 `~/.local/share/clec`。它自动限制一个当前版本和一个下载候选，单包上限为 2 GiB；下载前要求候选之外仍有 5 GiB 可用空间。更新校验通过后切换，旧引用明确失效。旧文件因打开的读取句柄无法删除时，返回 `cleanupPending`，下次同步先清理，失败则拒绝继续下载。这些自动规则只作用于 CLI 自己管理的文件，不会清理旧 canonical generation、原始资料或其他目录。

发布者只写新的输出目录。进程被强制终止时，可能留下同级 `.<输出目录名>.building`。重试同一路径前，先确认该发布任务已结束且没有进程使用其中的文件，再删除这一未发布 staging；不要删除已发布目录。消费端遇到无法自动确认 owner 的残留锁时也应先核对进程，不能按文件年龄猜测。

本轮开发与验证产物位于 `~/.cache/clec/runs/portable-cli-20261113`。完整发布文件与独立消费端安装各占一份数据空间；这些副本用于验证，不代表普通使用者需要保留两份完整数据。Node 22 的私有验证运行时是复现环境，也不包含在 CLI 的 npm 依赖中。
