# Backend E2E acceptance data

`development.jsonl` contains 45 development cases: the original 28 and 17 additional natural-retrieval cases. `held_out.jsonl` is frozen and reserved for a separate final evaluator; do not inspect it or use it to tune prompts, retrieval, thresholds, or implementation. This directory is annotation and a future run plan, not an executable suite or test results.

Each JSONL line is one case, with stable IDs. The original 28 remain largely source-directed and measure lookup as well as other behaviors; they should not be mistaken for natural retrieval. The 17 additions omit titles, filenames, episode IDs and quotation anchors from questions, and include a cross-source comparison. They use eight previously unused transcript paths, including a long group discussion; the development evidence spans 18 distinct paths, including a derived summary. Transcripts and summaries of an episode are not independent corroboration. This selection is not representative of full-corpus recall. The additions do not claim coverage of every original format, or that the corpus has been exhaustively checked for equivalent passages.

Every development case explicitly declares `conversation.mode`. A standalone case starts a fresh session. An ordered session starts fresh at turn 1, then submits each case in ascending turn order in the same session, preserving the actual preceding user and assistant messages; `previous_case_id` identifies the immediately previous case, and `expected_context` describes the antecedent, not a message to inject. Never send rubric or evidence to the system under test. Capture both turns, including an incorrect first response, and grade the second with that actual history; report upstream context failures separately. Ordered sessions are `split` (001→004), `rebalance-definition` (019→020), `rebalance-example` (022→023), `reserve` (029→030), and `ownership` (039→040). Case 022 now identifies the example in its own question. The last two sessions are new contextual follow-ups.

Evidence line numbers are 1-based inclusive in the exact UTF-8 file identified by `path` and SHA-256. `span_text` reproduces those lines and `required_short_quote` locates them; it is not mandatory answer wording. For DOCX extractions, `original_asset_path` and its hash identify the original binary while offsets address the extraction. Reconcile citations with the actual indexed source and version. Gold evidence is minimum support, not a mandatory exact source: accept independently verified equivalent original passages, with all required conditions and attribution. Evaluate forbidden inferences and uncertainty as well as required points. No numeric passing score is predeclared.

Transcripts are automatically generated and unverified against audio: codes, amounts, dates, speakers and completeness may be wrong. Extracted documents can omit layout or graphics. Financial and tax claims are attributed historical source claims, not verified facts or advice. Missing-evidence cases establish only what examined passages do or do not say; evidence elsewhere may support a different answer. Preserve the original collection unchanged. See [scenario-spec.md](scenario-spec.md) for execution and limitations. No backend or legacy tests were run for this annotation.
