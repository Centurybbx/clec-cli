# Real-service recorder: prepared, not run

Use only after the owner freezes a complete build and provisions a full hybrid generation. This revision has not been executed. Use a new schema-3 state directory and a separate new Pi directory; create and build the state under controlled setup, preserving their provenance. Never reuse old Pi history. Set `CLEC_PI_DIR` explicitly for every independently started API, QMD and build process as well as passing `--pi-dir` to the recorder; the recorder cannot inspect the environment of an already running service. Keep private credentials in the service environment, not command arguments or evidence. The lifecycle mode accepts a private key file and supervises only its own children; it is an initial partial scenario, not full lifecycle acceptance.

After a separately controlled catalogue and hybrid build, start the genuine services with the same isolated paths. Do not reindex during latency measurements. Preserve build/index provenance and establish full-corpus readiness independently. Record process observations separately for hybrid execution; a restart or first session does not prove a cold model or search cache. Unless supported by evidence, cache state is unknown. No native inference or retrieval-contribution claim follows from this recorder.

Paths and output must be distinct and evidence output must be new. The case file contains private rubrics; only questions are submitted. Preserve all JSONL frames, CLI logs, API/QMD logs, diagnostics and snapshots. The collector stores live and full replay envelopes, bounded to 10,000 frames and 8 MB per frame; an interrupted collection is an incomplete case, with prior frames retained. Checks compare GET, terminal, final events, history, full replay and ordered block citation IDs. Each citation is checked against real CLI source output, original hash, UTF-16 range, quote, version and generation. Source CLI responses are cached only within one run's citation audit, with each occurrence independently checked. Concurrent changes to CURRENT require investigation. Empty citations are explicitly inconclusive. All block claims, conditions, provenance, caveats and entailment require manual review; `validated` and mechanical PASS are not semantic approval.

Elapsed time runs from submission through audit, and includes replay/source checks; use timestamps in raw events to distinguish service timing. Calls and cost are only observable reported metrics, estimates rather than invoices; missing measurements are unknown. The four-call reservation caps admission, not billing. Failed runs remain failures and ordered successors use actual host history, including failed predecessors. An admission/recording error remains visible. Full lifecycle, provider-observed cancellation/crash, reconnect from intermediate cursor, restart/orphan policy, no-hits and all answerability variants require separate genuine observations; this recorder does not claim they occurred. Held-out access requires an explicit frozen final phase and a separately authorized operator; it must not be opened for development.
