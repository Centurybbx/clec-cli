## Live scenarios

1. **Ingestion to answer and citation.** Ingest the isolated real assets and build QMD. Record source hashes, authoritative SQLite source/version records and index identity. Send real questions including exact episode/code, paraphrase, cross-source and missing-evidence cases through streaming API, and a representative question through the shared CLI. Verify actual model output and citations against original passages and correct version; retrieve cited source through the supported interface. Record how many directed supplementary searches occurred from observable events/logs; at most one per request. Capture evidence for host budget limits rather than inferring them from answer length.
2. **Real source update and index consistency.** In the isolated copy only, preferably swap a real source for another already-existing real version containing a different actual passage, retaining provenance, before/after bytes and hashes. If no suitable version exists, use a clearly labelled controlled test-only mutation; it is not real financial truth and must never be presented as such. Re-ingest/reindex through supported operations. Ask a question whose answer differs across versions; verify source records, citation retrieval, search and answer all refer to a consistent committed version. During update, if the API permits concurrent querying, capture whether results are old or new and ensure each answer/citation is internally version-consistent. Restart and repeat. Restore or discard the isolated copy after evidence capture; do not alter originals. If synchronization semantics are unspecified, report observed behavior rather than inventing atomicity guarantees.
3. **Cancellation of a running live request.** Start a real streaming question with enough genuine retrieval/reading work to observe it in progress. Cancel using the documented interface while the request is active; record event and cancellation times, terminal status, and whether further output, retrieval, provider activity or billable use continues where observable. Verify session remains usable and persistent state is consistent. If completion races cancellation, record inconclusive and repeat with an appropriately longer genuine request, not an artificial injected delay.
4. **Real timeout and budgets.** Set an allowed short host time budget and issue a genuine live request requiring retrieval and Pi access. Record configured deadline, elapsed monotonic time, terminal status, output and any observed provider activity after timeout. Do not inject failures or simulate time. If it completes before deadline, record that it did not exercise timeout and retry with a valid tighter budget or longer real request. Separately observe documented token/search/cost budgets if supported, without assuming provider-side hard termination or unobservable costs.
5. **Restart persistence.** Complete an actual session, stop and restart the service normally using its documented lifecycle, then retrieve the session and cited source and send a follow-up. Compare session history, authoritative source versions, index identity and response/citations to the pre-restart record. Record any interrupted-request recovery behavior separately.
6. **Concurrency and isolation.** Submit two distinguishable actual requests concurrently to the same session and observe start, stream and terminal ordering; check they serialize according to the advertised contract and that neither turn is lost or mixed. Then issue distinguishable simultaneous requests in two sessions; verify each output/history/citation belongs to its own session and no conversational context leaks. Use timestamps and session/request IDs, not a presumed speedup, as evidence.
7. **Cold/warm latency and observed costs.** Define cold precisely using supported service/index lifecycle and state what remains cached externally; run a fixed representative selection after cold start, then repeat warm with the same source/index/provider settings. Capture time to first event, first answer token where distinguishable, completion and citation retrieval, plus failures and sample counts. Report raw measurements and conditions rather than a general performance claim. Record provider-reported token usage/cost or billing only if actually observable, its units and coverage; otherwise mark unavailable. No invented price or arbitrary performance threshold.

For each scenario retain a dated evidence log, outputs/citations, source and index versions, explicit pass/fail/inconclusive rationale against the delivered contract, and limitations. A failure or unsupported feature is evidence, not a reason to silently replace the real path. Do not publish secrets or private source content unnecessarily.
