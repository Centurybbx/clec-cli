# CLEC Native Phase 4 Static Distribution Protocol

This protocol defines how the native CLI acquires `clec-native-v2` packages from static HTTP hosting and bootstraps an empty cache. It does not change retrieval ranking, corpus format, or `--sag2` support. Stage 3 quality issues remain open and unchanged.

## Origin and network rules

1. **Manifest location validation.** `sync --manifest LOCATION` accepts a local filesystem path, a local `file:` URL without a remote host, or an HTTP(S) URL. Windows drive paths and ordinary filesystem paths remain distinct from URL schemes. URLs with credentials or `#` fragments are rejected with `INVALID_ARGUMENT`. Public transport requires `https:`. Plain `http:` is permitted only for literal loopback IPs or `localhost` resolved exclusively to loopback addresses.
2. **Origin precedence and persistence.** Explicit `sync` selects the explicit `--manifest` argument first, then saved `active.json.manifestPath`, then the built-in default origin if configured. No new configuration file, public environment variable, or endpoint selector is introduced. Only a successful activation persists the canonical local path or normalized original request URL into `active.json`. Expiring final redirect URLs are never persisted.
3. **Optional `artifactUrl` and `--artifact-url`.** `ReleaseManifest` adds an optional `artifactUrl` field omitted when absent so default publisher bytes stay identical. `clec-publish` accepts an optional `--artifact-url` HTTPS URL without altering SQLite or zstd content. Local sync always reads the sibling `artifact` file regardless of `artifactUrl`. Remote sync uses `artifactUrl` when present and otherwise resolves `artifact` relative to the final manifest response URL after redirects. HTTPS-to-HTTP downgrade is rejected with `INVALID_PACKAGE`.
4. **Offline policy.** `--offline` forbids all HTTP requests, including manifest fetches, redirects, and `--dry-run` checks. Explicit or saved remote `sync` under `--offline` fails with `OFFLINE_REQUIRED` (exit 2) and issues zero HTTP requests. Local `sync` remains permitted under `--offline`.
5. **Absent production default.** When no authoritative production default URL is compiled in, `schema.defaultConfigured` is `false`. Cold unconfigured evidence commands fail honestly with `NO_DATA` and no fabricated URL. Test default injection exists only in internal test harnesses or feature-gated fixture builds.

## Transport and validation bounds

1. **HTTP client policy.** Consumer transport uses `reqwest` blocking mode with Rustls default certificate verification, `redirect::Policy::none()`, `retry::never()`, and automatic gzip/brotli/deflate/zstd decoders disabled. Requests send `Accept-Encoding: identity`, and non-identity `Content-Encoding` responses fail with `TRANSFER_FAILED`.
2. **Redirects and deadlines.** At most five `301`, `302`, `303`, `307`, or `308` redirects are followed manually. Each hop validates scheme, credentials, fragments, and non-downgrade before sending. Shipped deadlines are 10 seconds to connect, 30 seconds total for manifest retrieval across all redirects, and 300 seconds total for artifact retrieval across all redirects. Only HTTP `200` provides a valid body. Signed URL query strings are omitted from error messages.
3. **Streaming size and integrity checks.** Manifest reads are bounded to 1 MiB plus one sentinel byte before JSON parsing. Remote artifacts stream directly into an owned `.incoming.zst.tmp` file in `--data-dir` guarded by a drop cleanup handle. Declared `Content-Length` values must match `compressedBytes`, and actual bytes beyond `compressedBytes` fail immediately. Short clean EOF fails with `INTEGRITY_MISMATCH` (exit 5); transport errors and deadlines fail with `TRANSFER_FAILED` or `TRANSFER_TIMEOUT` (exit 4).
4. **Shared lifecycle and rollback.** Remote and local paths converge at the same lock-protected decompression, `CorpusStore::validate_staging_db`, `--max-bytes` output preparation, and atomic `active.json` replacement. Same-release reuse still downloads and verifies the incoming zstd stream and decompressed digest. Temporary `.incoming.zst.tmp` files are excluded from projected `storageBytes`. Every pre-commit failure preserves prior active SQLite state and `active.json`.

## Cold bootstrap and dry-run

1. **Prepared request boundary.** `search`, `read`, and `sources` validate all store-independent flags, typed IDs, date bounds, numeric limits, and search query tokenization before opening or bootstrapping `--data-dir`. Invalid inputs fail with zero network or cache writes.
2. **Cold bootstrap rules.** Valid `search`, `read`, and `sources` attempt cold bootstrap only when `active.json` is absent and a built-in default origin is configured. Under `.sync.lock`, bootstrap rechecks `active.json` to avoid duplicate downloads. Corrupt `active.json`, missing active SQLite files, and `--release` mismatches never trigger automatic replacement. `status`, `schema`, `--help`, and `--version` stay local and write-free.
3. **Bootstrap query failures.** Because bootstrap installs the verified cache before running the query, a subsequent missing valid ID (`EVIDENCE_NOT_FOUND`), release-pin mismatch (`VERSION_UNAVAILABLE`), or query output-budget error (`OUTPUT_BUDGET_TOO_SMALL`) leaves the verified cache installed while emitting structured stderr JSON and empty stdout.
4. **Manifest-only `sync --dry-run`.** `--dry-run` validates origin resolution, offline policy, and the bounded manifest only. It returns a plan containing selected origin, release hash, compressed and expanded sizes, counts, and whether that release is currently active. It performs zero `--data-dir` writes and zero artifact GET requests.

## Required verification gates

1. **Implementation gate.** Passes when `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`, `cargo build --release --locked`, Phase 2 unit/blackbox regressions, Phase 3 synthetic regressions, the real-binary Phase 4 HTTP/HTTPS/offline/bootstrap/dry-run matrix in `evaluation/clec-v1/phase4/verify_phase4.py`, a real-CLI 30-second manifest stall check, and a full `clec-native-v2` corpus local HTTP capacity run all pass.
2. **Production default endpoint gate.** Remains separately open until a real static production manifest and artifact endpoint are published, compiled in as the default, and verified via cold default search followed by offline repeat.
