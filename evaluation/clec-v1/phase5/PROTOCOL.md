# CLEC Native Stage 5 SAG2 and Shared Transport Protocol

This protocol defines the shared bounded HTTP transport extraction, explicit `clec search --sag2` retrieval (`sag2_native_v1`), strict Jev Decisions wire validation, resource admission bounds, tagged response and error schemas, and the mandatory verification matrix. Default `clec search`, corpus format `clec-native-v2`, Stage 4 static distribution policy, and Stage 3 quality status remain unchanged. Live provider availability and host answer quality remain separate open gates.

## 1. Unit Zero shared transport parity rules

1. **Private transport boundary.** `native/src/http_transport.rs` (`pub(crate) mod http_transport`) owns the bounded network worker lifetime: synchronous per-hop DNS resolution, literal-IP bypass, HTTP loopback exclusivity check, `resolve_to_addrs` pinning with `ImmediateFailResolver`, direct-only `reqwest` blocking Rustls client setup (`no_proxy()`, `redirect::Policy::none()`, `retry::never()`, gzip/brotli/deflate/zstd disabled), `Accept-Encoding: identity`, `Content-Encoding: identity` validation, capacity-one `sync_channel` streaming in `65,536`-byte chunks up to `max_body_bytes` (including one sentinel byte), `Arc<AtomicBool>` cancellation, absolute deadline enforcement across DNS/setup/send/read/cleanup, and `WorkerResponse` destruction (`Response` before `Client`) before publishing `TransferEvent::Finished`.
2. **Typed request and neutral failure boundary.** `HttpRequest` is a closed enum (`Get { url }` and `Post { url, headers, body }`) owning plain values without `Debug` on headers/body. `WorkerSession` is a plain function pointer `fn(HttpRequest, &WorkerContext) -> Result<(), TransportFailure>` with exactly two production implementations: distribution's GET redirect session and Jev's single-POST session. `TransportFailure` exposes closed neutral categories and static reason discriminants only, with zero raw response bodies, header values, credentials, or reqwest error chains. `RemoteTransfer::drop` cancels and disconnects without joining.
3. **Distribution policy retention.** `native/src/distribution.rs` keeps URL syntax validation, query redaction, `ManifestLocation`, `ArtifactLocation`, `TransferPolicy`, `TransferPhase`, `MAX_REDIRECTS = 5`, GET redirect-loop and HTTPS-downgrade rejection, status `200` requirement, local reads, SHA-256 verification, staging temp-file cleanup, and `.sync.lock` ownership. Test hooks migrate once into `http_transport` under `#[cfg(any(test, feature = "test-hooks"))]` with `native/src/cli.rs` updated to that single registry.
4. **Parity predicate.** Before any SAG2 feature code is added, the extracted build must pass all 44 Rust tests, 5 Phase 2 capacity tests, 20 Phase 3 synthetic tests, 10 Phase 2 blackbox checks, 9 Phase 4 matrix groups (including the 30-second shipped stall), and 7 DNS/proxy/cleanup regression groups with unmodified fixture parameters and assertions, preserving the 100 ms DNS deadline, 1.5-second stall, under-750 ms exit tolerance, zero target requests after latch release, lock reacquisition, byte-identical active state, and fixed buffering.

## 2. Mode authorization, credentials, and endpoint validation

1. **Explicit mode boundary.** `clec search` runs in `SearchMode::Local` by default and enters `SearchMode::Sag2(ValidatedJevConfig)` only when `--sag2` is passed. Default local search performs zero credential reads and zero Jev API calls even when keys are configured. `--offline --sag2` fails with exit code 2 before credential access, DNS, bootstrap, or HTTP. Passing `--sag2` on any subcommand other than `search` (including `sync --dry-run --sag2`), or passing `--key-file` without `--sag2`, fails with exit code 2 before I/O or network access.
2. **Pre-bootstrap validation order.** All CLI flags, `--max-bytes >= 1`, `--offline --sag2` conflict, query syntax and bounds (1 to 4 queries, 1 to 512 UTF-8 bytes, 1 to 64 distinct lexical terms), `--limit` (`1..=20`, default 10), `--per-work` (`1..=5`, default 2), `--date-from <= --date-to`, typed IDs (`--work`, `--source`, `--release`), conservative minimum-envelope `--max-bytes` admission for `--sag2` (`minimum_sag2_search_envelope_bytes` for the parsed `PreparedSearch` and format, before opening `--key-file` or `--data-dir`, preserving local Stage 4 bootstrap behavior), and SAG2 target/credential configuration (including canonical HTTP/1.1 header block size with a 1-digit `Content-Length` lower bound and strict UTF-8 env decoding without fallback) are validated before `ensure_current_store` opens `--data-dir` or performs cold bootstrap.
3. **Endpoint and credential precedence.** Default endpoint is `https://openrouter.ai/api/alpha/decisions`. Default model is `typesafe/jev-1.14`. `JEV_BASE_URL` and `JEV_MODEL` override defaults when non-empty. A `JEV_BASE_URL` whose path ends with neither `/decisions` nor `/systemone` (after trimming trailing slashes) has `/systemone` appended. Endpoint validation rejects URL credentials, queries, fragments, NUL bytes, non-HTTP(S) schemes, and non-HTTPS targets except literal loopback IP HTTP (`http://127.0.0.1:...`, `http://[::1]:...`). `--key-file PATH` takes highest credential precedence with no fallback if unreadable, empty, or header-invalid. Otherwise OpenRouter targets (`openrouter.ai`) read `OPENROUTER_API_KEY`, and explicitly configured non-OpenRouter targets read `JEV_API_KEY` without falling back to `OPENROUTER_API_KEY`. Automatic `.env` discovery, literal key CLI flags, and model/provider fallback are forbidden. Secrets are trimmed, checked for valid `Authorization: Bearer <token>` header syntax and the 8 KiB canonical HTTP/1.1 request header block cap, and never serialized or included in errors or logs.

## 3. `sag2_native_v1` retrieval, expansion, DPP, and provenance

1. **Pinned read snapshot.** A single `CorpusStore` on `<release>.sqlite` holds one scoped SQLite read snapshot (`BEGIN` / `ROLLBACK` under `PRAGMA query_only=ON`) across all rounds, preventing cross-release evidence mixing even if `active.json` changes concurrently. `--release` mismatch returns `VERSION_UNAVAILABLE` (exit 3) before any scoring call.
2. **Round 0 initial retrieval.** Shared crate-private functions in `native/src/retrieval.rs` collect BM25 + RRF (`k=60`) candidates across the 1 to 4 user queries (up to 100 per query, inheriting all search filters) and select the global top 100 before work-diversity truncation. Empty candidates terminate naturally with `ok: true`, `hits: []`, `stopReason: "no_candidates"`, zero Jev calls, and zero DF lookups. Materialized passages come exclusively from `CorpusStore::read_passage` / `load_verified_passage_core` raw-blob byte-span verification.
3. **Round 0 Jev scoring and seed selection.** All Round 0 candidates (up to 100) are packed and scored against `queries[0]` (`original_question`) with empty prior evidence. Seeds are the top 10 by `(jev_score desc, round0_retrieval_rank asc, passage_id asc)`.
4. **Local expansion term derivation.** At most 20 terms are derived locally from seed passage text using native sentence splitting, native lexical tokenization (`normalize_for_search` + `segment_normalized` excluding stopwords and all original user query terms), corpus body document frequency from SQLite FTS5 (`SELECT count(*) FROM search WHERE search MATCH 'body_tokens : "..."'`), left-to-right sentence query-overlap weighting, and `0.5 + 0.5 * (seed_jev / max_seed_jev)` seed weighting, with ties broken by stable UTF-8 lexical order. A shared per-run `TermDfCache` caps distinct DF lookups at 4,096 across expansion and DPP. If zero expansion terms qualify, the run terminates naturally with `stopReason: "no_expansion_terms"` and retains the Round 0 scored pool.
5. **One expansion round and second scoring.** Each derived term (at most 20) is queried once via excluded-ID BM25 (`LIMIT 100`, inheriting all search filters, excluding Round 0 seen IDs). Lists merge round-robin in ranked-term order, deduplicate, and stop at 100 new IDs. Total candidate SQL queries per run are at most 24 (`4 + 20`). If zero new IDs match, the run terminates naturally with `stopReason: "no_expansion_candidates"` and retains Round 0 scores. Otherwise the second scoring pool carries initial top 5 plus the 10 seeds plus up to 100 new candidates (deduplicated, at most 115 candidates; at most 215 scored occurrences total). Every Round 1 batch carries all selected Round 0 seeds as whole records with `previous_jev_score`. All Round 1 pool candidates are scored once.
6. **DPP diversity, work diversity, and native rematerialization.** The retained pool is sorted by `(jev_score desc, round asc, genuine_rrf_score desc, retrieval_rank asc, passage_id asc)`. Greedy Cholesky DPP runs over the top 10 using L2-normalized native lexical TF-IDF vectors (`1 + ln(tf)` times `ln((1 + N) / (1 + df)) + 1`) stored in sorted `BTreeMap` / sparse `(String, f64)` order with two-pointer sorted dot products so all floating-point reductions are process-deterministic, handling empty/zero vectors, zero scores, duplicate vectors, and exhausted residuals deterministically without `NaN`. Existing `apply_work_diversity` (`limit`, `per_work`) selects final passage IDs, which are rematerialized from the same pinned store via `read_passage`. Model outputs can never invent or alter IDs, text, spans, cues, sources, endpoints, filters, or next actions. Genuine `rrfScore` and `matchedQueries` stay strictly separate from `jevScore` and `dppOrder`.

## 4. Wire validation, transport limits, output budgets, and errors

1. **Strict response validation and checked accounting.** JSON parsing rejects invalid UTF-8, duplicate object keys, and trailing non-whitespace bytes. The root must be an object without non-null `error`, carrying non-empty bounded `model` (<= 256 bytes, failing on drift across batches within one run) and `answers` matching the submitted batch question keys one-to-one. Each answer must be a closed `{"type": "noul", "noul": <number>}` object with a finite JSON number in `0.0..=1.0` (no booleans, strings, null, refusals, or extra `text`/`quote`/`span`/`tool` fields). Optional `usage` when present must be an object with non-negative integer `input_tokens` and `output_tokens` and optional finite non-negative `cost`; absent `usage` or `cost` remains explicitly unknown rather than zero. Aggregate `input_tokens` and `output_tokens` use checked `u64` addition and aggregate `cost` requires finite `f64` summation before committing `successful_batches`, `actual_model`, or usage/cost provenance; any overflow fails closed with `JEV_INVALID_RESPONSE` (exit 5) while retaining spent `http_attempts` and observed `response_bytes`. Unrelated bounded top-level metadata is discarded without reflection.
2. **Bounded POST scheduling and per-request limits.** Revision `sag2-native-v1-batched-full-context` prepares every batch for a round before dispatch and runs up to four requests in flight. It consumes results in dispatch order and drops outstanding transfers on an error. The transport disables redirects and retries.

   - Every model has an 8 KiB canonical HTTP/1.1 header block limit, including the seven generated headers and terminating CRLF. Configuration uses a one-digit `Content-Length` before bootstrap, and round dispatch prechecks every finalized batch's exact header block size before sending the first request of that round. HTTP/2 framing may differ.
   - Every POST has a 65,536-byte serialized UTF-8 JSON body limit, at most 32 questions, and a 128 KiB response limit with a one-byte overflow sentinel. The 5 s connect timeout and 20 s request timeout are clamped to the 90 s run deadline, which also bounds local retrieval.
   - Exact requested model IDs `typesafe/jev-1.14` and `typesafe/jev-1.14-20261014` use `calibrated_jev_1_14_body_bounded`. The planner uses the body and question-count limits for admission. Both estimate cap fields in `limits` are `null`. Each finalized batch contributes `ceil(2 * body_bytes / 5) + 42 * question_count + 4` to `consumption.estimatedTokenUnits` with basis `jev_1_14_synthetic_forecast_non_blocking`. The synthetic forecast is informational and reported separately from provider usage.
   - All other requested model IDs, including `~typesafe/jev-latest`, use `uncalibrated_conservative_byte_bound`. Admission also requires `2 * (shared_bytes + sum(question_bytes) + 4096)` to stay within 32,000 units for a singleton and 64,000 units for a batch. Shared JSON bytes are counted once per batch. The basis is `uncalibrated_conservative_byte_bound_shared_state_once_per_batch`.
   - If any singleton with full scoring context exceeds an admission limit, the round fails with `SAG2_BUDGET_EXHAUSTED` before dispatch. Every admitted batch includes the full seed set and `contextOmittedCount` is zero. The CLI accounts for request attempts, bytes, and estimated units across the run. `responseBytes` counts consumed response chunks, including an observed overflow byte.

3. **Output budgets, schemas, and error exit mapping.** `SearchOutput` is tagged by `mode` (`local` vs `sag2`). Whole-item `fit_search_budget` converges exact serialized UTF-8 byte length including metadata, escaping, and trailing newline, returning the complete lead list within `--max-bytes` or failing with `OUTPUT_BUDGET_TOO_SMALL` (exit 2) and empty stdout. `SchemaData` reports `phase: "phase5"`, `providerVerified: false`, removes `sag2` from `unsupportedFeatures`, and derives all success and error schemas (including redacted `sag2Stage` counters) directly from Serde and Clap. Error exit codes: configuration/arguments/offline/budget 2, missing data/release/evidence 3, provider transport/HTTP status/timeout/lock/IO 4, invalid provider response/integrity 5, internal 1. No partial-success output or silent fallback to local RRF occurs on SAG2 failure.

## 5. Mandatory real-CLI verification matrix (10 case groups and negative controls)

The rerunnable Rust integration driver (`native/tests/sag2_protocol.rs`) executes the compiled `clec` and `clec-publish` binaries against synthetic corpora and an authoritative loopback HTTP/HTTPS mock server logging `(sequence, method, path, body_bytes, parsed_json, question_keys, original_question, candidate_texts, model, auth_present, auth_matches_sentinel)` without ever recording raw secrets:

1. **Zero-API and pre-bootstrap validation.** Warm default `search`, `--help`, `--version`, `schema`, `status`, `read`, and `sources` produce 0 Jev requests even with `OPENROUTER_API_KEY` and `JEV_API_KEY` set. Cold `--offline` and `--offline --sag2` produce 0 distribution and 0 model requests. Invalid queries, limits, dates, typed IDs, `--sag2` on `sync --dry-run` or `status`, `--key-file` without `--sag2`, missing keys, unreadable/empty key files, invalid `JEV_BASE_URL` (credentials/query/fragment/remote HTTP/http localhost), and tiny `--max-bytes` all fail before `--data-dir` creation or bootstrap.
2. **One-hop synthetic chain discovery.** An invented two-hop bridge fixture (no benchmark or CLEC evaluation data) where Round 0 finds passage A (mentioning an invented bridge entity) and misses passage B (only matching the bridge entity) fails to recover B in default local search and succeeds in `search --sag2`, proving two-round scoring, exact Round 0 seed context in Round 1, and bridge-passage recovery.
3. **Request log provenance, credential routing, and no-retry/no-redirect.** Logs verify `auth_present`, `auth_matches_sentinel` for `--key-file` > `OPENROUTER_API_KEY` (OpenRouter) / `JEV_API_KEY` (custom target, never OpenRouter fallback), requested model, normalized `/systemone` or `/decisions` path, exact candidate text, and total attempt/occurrence counts. Statuses `408`, `429`, `499`, `500`, connection drop, timeout, and malformed JSON each incur 1 attempt with 0 retries. `301`, `302`, `303`, `307`, `308` redirects (same-host and cross-host) make 0 requests to the redirect destination and forward no `Authorization`.
4. **Strict wire rejection and error redaction.** Duplicate JSON keys, trailing data, invalid UTF-8, wrong root type, non-null `error`, missing ID, extra/unknown ID, null answer, refusal shape, wrong `type`, boolean score (`true`/`false`), string score (`"0.5"`), `NaN`/inf/out-of-range (`-0.1`, `1.1`) score, closed-answer injection (`quote`, `text`, `span`, `tool`), missing/empty/oversized model, model drift across batches/rounds, malformed `usage` (`null`, non-object, negative/float/bool token counts, negative/string cost), body-echoed sentinel, and oversized headers/CL/chunked responses all exit with expected codes, empty stdout, and stderr free of secrets, raw provider bodies, or credential-bearing URLs.
5. **Prompt injection and unsubmitted-ID confinement.** Malicious corpus instructions demanding network requests, new endpoints, filter changes, tools, or secrets cannot alter request targets, headers, filters, or output attribution. A response returning a valid-format DB-existing `PassageId` not in the submitted batch fails validation.
6. **Exact evidence reconstruction, integrity errors, and snapshot isolation.** Chinese UTF-8, escaped characters, and `.srt` subtitle cue reconstruction match raw source bytes byte-for-byte. Independent corruptions of `blobs`, `passages.text`, and `passage_spans` trigger `INTEGRITY_MISMATCH` (exit 5). Active-release swap (`active.json`) mid-run between Round 0 and Round 1 produces zero cross-release evidence mixing.
7. **Algorithmic bounds and edge cases.** Verifies global top-100 cut before diversity/limit, 1 to 4 query fusion, filter inheritance (`--work`, `--source`, `--role`, `--date-from`, `--date-to`) on expansion Round 1 submitted request logs, seen-ID exclusion for new expansion candidates (while carried seeds/top-5 are intentionally rescored), authored round-robin merge order across expansion terms, deterministic tie breaking on Jev scores and expansion terms (20-term cut), zero scores, empty/zero DPP vectors, duplicate DPP vectors, varied-frequency symmetric DPP vectors across processes, per-work fill-back, and pre/post default local `execute_search` order/evidence parity against the accepted pre-SAG2 release binary.
8. **Budgets, packing, deadlines, and fixed-point output.** Exercises exact and one-over canonical header and per-response sizes, partial response accounting, the model-specific singleton and batch limits, full seed context, 24 SQL candidate queries, 4,096 distinct DF lookups, and whole-item output sizing. A gated loopback test verifies four requests in flight and completes 35 successful requests covering all 70 candidates, with 128 KiB responses. The fixture also verifies DNS, setup and cleanup deadlines, named-host TLS/SNI, proxy isolation, and pre-I/O output admission.
9. **Process termination cleanup.** Terminating a waiting `clec search --sag2` child mid-request results in zero subsequent mock requests; the driver cleans up all child processes and servers.
10. **Negative controls.** The driver explicitly runs negative-control checks confirming that: (a) a server returning an unsubmitted DB-known ID fails with `JEV_INVALID_RESPONSE`, (b) mutated raw bytes fail with `INTEGRITY_MISMATCH`, (c) an isolated second-stage score reversal (with Round 0 scores held fixed) reverses the top hit, and (d) a genuinely extra mock HTTP request fails the driver's shared `assert_exact_request_count` assertion with the predicted count mismatch message.
