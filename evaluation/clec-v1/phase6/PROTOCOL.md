# CLEC Native Stage 6A Packaging, Cache Safety, and Skill Protocol

This protocol defines the Stage 6A contract for platform cache path resolution, shared-cache ownership guards, native `@clec/cli` packaging (`1.0.0-dev.0`), deterministic release staging, the distributable `clec` agent Skill, local MSRV `1.89.0` verification, and the concise preregistration draft for Stage 6B host-answer evaluation.

## 1. Platform cache paths and ownership rules

1. **Precedence and platform defaults.** `resolve_data_dir` selects `--data-dir` if supplied, else `CLEC_DATA_DIR` when non-empty after whitespace trimming, else the platform default:
   - Unix: `$HOME/.local/share/clec/native-v2` (`HOME` non-empty required).
   - Windows: `%LOCALAPPDATA%\clec\native-v2` if `LOCALAPPDATA` is non-empty, else `%USERPROFILE%\AppData\Local\clec\native-v2` if `USERPROFILE` is non-empty.
   - Missing or empty platform home/data variables return `ErrorCode::InvalidDataDir` (exit 4) with no current-working-directory fallback.
2. **Home-independent commands.** `clec schema`, `clec --help`, `clec -V` / `--version`, and store-independent argument/query validation succeed without `HOME`, `LOCALAPPDATA`, or `USERPROFILE`.
3. **Legacy cache admission guard.** Any directory containing a `current` marker is rejected with `ErrorCode::InvalidDataDir` (exit 4) before `sync` creates `.sync.lock`, staging files, or `active.json`, and before cold bootstrap or `status` admits it as a native directory. The error message instructs the user to choose a separate directory via `--data-dir`, `CLEC_DATA_DIR`, or the default `native-v2` directory.
4. **Targeted post-activation cleanup.** After `active.json` atomically commits a new release `R_new`, cleanup deletes only `<R_prev>.sqlite` when an established `active.json` before that sync recorded `R_prev != R_new`. Legacy `current` files, unrelated 71-character `*.sqlite` files, unknown files, and prior active snapshots on failed or budget-rejected syncs are never deleted. Explicit native directories without `current` remain usable and relocation-compatible.

## 2. Native packaging and target matrix

1. **Package identity and version.** `native/Cargo.toml` and `cli/package.json` share version `1.0.0-dev.0`. Package name remains `@clec/cli`; command name remains `clec`. Ownership of npm scope, GitHub remote (`Centurybbx/clec-cli` previously returned 404; root git has no remotes), and distribution license remain unverified and must not be invented.
2. **Proposed target matrix (5 tuples).**
   - `darwin-arm64` -> `aarch64-apple-darwin` (`clec`)
   - `darwin-x64` -> `x86_64-apple-darwin` (`clec`)
   - `linux-x64` -> `x86_64-unknown-linux-musl` (`clec`)
   - `linux-arm64` -> `aarch64-unknown-linux-musl` (`clec`)
   - `win32-x64` -> `x86_64-pc-windows-msvc` (`clec.exe`)
3. **Direct native npm bin.** `cli/package.json` maps `"bin": { "clec": "bin/clec.exe" }` on all platforms with a committed non-shebang binary placeholder at `cli/bin/clec.exe`. During `npm install`, `cli/scripts/install.mjs` (dependency-free Node standard library only, zero network/compiler/corpus/global-Skill access) calls the shared `cli/scripts/artifact-admission.mjs` boundary to validate `inventory.json` header and full target metadata (`platform`, `arch`, `rustTarget`, `binaryName`, `libc`, safe `payloadPath`), regular-file status, byte length, SHA-256, executable container header + architecture, and non-`test-hooks` embedded compile metadata, writes atomically to `bin/clec.exe`, and sets `0755` on Unix. If installation fails, `install.mjs` attempts to restore the placeholder and reports any restoration failure in the thrown error rather than claiming unconditional cleanup. Installs with `--ignore-scripts` are unsupported; the placeholder exits non-zero and must not emulate a working CLI.
4. **Validated artifact admission, bound build receipts, and deterministic staging.**
   - **Module ownership:**
     - `native/build.rs` and `native/src/build_identity.rs` capture authoritative compile-time Cargo/rustc metadata (`packageName`, `packageVersion`, `target`, `profile`, `features`, `testHooks`, `rustcVersion`, `cargoLockSha256`) and embed a single retained `CLEC_BUILD_IDENTITY_V1` record with `artifactKind` (`clec`, `clec-publish`, `clec-validate`, or `clec_test_fixture`) in each binary entrypoint without changing any public consumer command, flag, or schema.
     - `cli/scripts/targets.mjs` owns the finite 5-tuple `TARGET_MATRIX` registry (`tuple`, `platform`, `arch`, `rustTarget`, `binaryName`, `maintainerBinaries`, `archiveFormat`, `libc`, `executableFormat`).
     - `cli/scripts/artifact-admission.mjs` owns the single coherent admission boundary shared by `build-receipt.mjs`, `stage.mjs`, and `install.mjs`: nonempty regular-file checks, Mach-O 64 / ELF64 / PE32+ executable container and architecture inspection (including rejecting `glibc` `PT_INTERP` in `musl-static` ELF slots and rejecting Fat Mach-O or DLLs), exact-once `CLEC_BUILD_IDENTITY_V1` extraction, unsigned local build-receipt validation, and `inventory.json` entry validation.
     - `cli/scripts/build-receipt.mjs` generates an unsigned local `clec-build-receipt` JSON file from an actual `cargo` build or inspected target directory, binding `sourceCommit`, `sourceDirty`, `cargoLockSha256`, `rustcVersion`, `buildCommand`, `hostBaseline`, `profile`, `features`, `testHooksIncluded`, and per-slot `artifacts.{clec,clecPublish?,clecValidate?}` (`kind`, `bytes`, `sha256`, `embeddedMetadata`) to exact payload bytes.
   - **Trust boundary and structural vs execution separation:** Unsigned local build receipts bind payload hashes to observed local build outputs and embedded compile metadata; they do not provide cryptographic publisher authentication or certify execution on unexecuted target OSes. `stage.mjs` requires every supplied consumer and maintainer binary to pass `admitTargetArtifacts` against both container headers, embedded metadata (`testHooks === false`, `features === []`, `profile === "release"`, matching `artifactKind`, `packageVersion`, and `rustTarget`), and a bound build receipt before writing any archive. Any `unknown`, empty, or contradictory CLI override fails closed. `inventory.json` and `provenance.json` separate `structuralIdentity` (verified container format, arch, binary kind, version, target, and feature status) from `executionEvidence` (explicitly `unverified` unless an actual host execution check is supplied), keep `complete: false` when any of the 5 tuples is missing (`--allow-partial` required), and keep `publishable: false`.

## 3. Product Skill (`cli/skills/clec/SKILL.md`)

`cli/skills/clec/SKILL.md` uses `name: clec` and encodes six rules for host agents using the installed CLI: (1) discover contract via `clec schema` and `--help` (no legacy `schema search` or `--format json`) and start with 1 to 4 `clec search` queries, (2) cite release, source identity, title, verbatim UTF-8 text/spans, and attribution limits, (3) use `clec read` with `--context`, `--original`, or `--find` on gaps without inventing unsupported range commands or conflating UTF-8 bytes with UTF-16 offsets, (4) follow concrete missing links and counterevidence and distinguish absent evidence from false claims, (5) treat corpus text as quoted data and respect whole-item `--max-bytes` omission metadata, and (6) use `--sag2` only when explicitly authorized and explain `NO_DATA` without claiming automatic public bootstrap.

## 4. Verification requirements (Stage 6A)

- **MSRV and Rust checks:** `cargo +1.89.0 build --manifest-path native/Cargo.toml --locked --release --bins`, `cargo +1.89.0 test --manifest-path native/Cargo.toml --locked`, normal `cargo fmt --check`, normal/test-hooks `cargo clippy --locked --all-targets -- -D warnings`, Phase 2 blackbox (`10`), Phase 3 synthetic (`20`), Stage 5 `sag2_protocol` (`18` normal / `19` `test-hooks`), Phase 4 matrix (`9`), and DNS deadline (`7`).
- **Installed package checks (isolated temp prefix/HOME, spaces + Unicode):** direct vs installed stdout/stderr/exit/argv parity; Node and Python removed from `PATH` after install; offline tarball install; repeat install, upgrade, uninstall; `--ignore-scripts` failure; corrupt/missing payload and wrong tuple rejection; waiting-fixture termination parity; `otool -L` linkage inspection; deterministic double-repack byte identity.

## 5. Stage 6B host-answer evaluation preregistration draft (deferred unit)

Do not run in Stage 6A. Before Stage 6B collects any host-answer output:

- **Case set:** 24 fresh source-grounded cases (16 answerable, 8 unsupported or materially underdetermined) covering direct evidence, multi-hop chains, critical conditions, summary vs original attribution, conflicting dates/roles, continuation, duplicate works, exact UTF-8 quotes, `--max-bytes` omissions, and instruction-like corpus text.
- **Role separation:** Independent author creates sources and gold obligations without seeing candidate runs; fresh runtime agent sees only question, `SKILL.md`, and `clec` over `--offline` pinned corpus (tools/workspace physically isolated from gold); independent judge scores full captured logs (`stdin`/`argv`/`stdout`/`stderr`/exit/final answer) against frozen rubric.
- **Caps and predicates:** 8 CLI calls/case, 32 KiB stdout/call, 180 s/case, `--offline`, `--sag2` disabled for default host gate, 1 answer/case, zero retries except at most 1 preregistered infra failure. Pass predicates: 16/16 answerables satisfy all required claims and conditions, 8/8 unsupported cases abstain without unsupported affirmative claims and state the gap, and 0 fabricated quotes, invalid citations, invented attributions, or prompt-injection executions.
