# CLEC Native Stage 6A Linux ARM64 Container Verification Protocol

This protocol defines a bounded, rerunnable Linux `arm64` container verification unit for `clec-native` (`1.0.0-dev.0`) and `@clec/cli` (`1.0.0-dev.0`) stacked on accepted Stage 6A commit `3999d3ef4cd96ddbf03b39aaba0395dccb3996d8` (native source unchanged since `795deb33f149cbf7547849970429acc5f5d63f70`).

## Scope and explicit non-claims

This unit tests real Linux `aarch64` container execution on a local macOS `arm64` Docker Desktop LinuxKit host (`OSType=linux`, `Architecture=aarch64`, Docker `28.0.4`). Passing this unit closes ONLY the `linux-arm64` (`musl` and `glibc` guest) container execution evidence gap under these controls. It does NOT verify:

- bare-metal Linux hosts, systemd/init environments, or arbitrary minimum kernel baselines,
- `darwin-x64`, `linux-x64`, or `win32-x64` (`cmd`/PowerShell) execution,
- Stage 6B host-answer quality, live Jev provider calls (`providerVerified: false`), production manifest URLs (`defaultConfigured: false`), npm/GitHub/license rights, or Stage 3 retrieval quality.

Resource and isolation bounds:

- All containers and volumes use task-prefixed names `clec-linux-arm64-*`.
- No `--privileged`, no Docker socket mount, no host root or user home mount, and no secrets mount.
- Source files enter the builder container via a read-only (`:ro`) mount of a clean 38-file export generated by `tools/export_cli.py`, isolated from `.git`, host `.cache`, and private corpora.
- Builder containers run sequentially with bounded CPU (`--cpus 2`), memory (`--memory 4g`), `CARGO_BUILD_JOBS=2`, and `CMAKE_BUILD_PARALLEL_LEVEL=2`.
- Consumer, maintainer, and negative-control containers run with `--network none`, `--cpus 2`, `--memory 1g`, and read-only rootfs where writable `/tmp` and task work directories are explicitly mounted.
- Never run `docker system prune`, `docker image prune`, `docker volume prune`, or delete pre-existing images, containers, or volumes. Clean only `clec-linux-arm64-*` containers, volumes, and intermediate Cargo build artifacts after retaining binaries, full logs, receipts, and stage inputs.

## Provenance and receipt honesty

`cli/scripts/build-receipt.mjs --run-build` executes `cargo` on the macOS host, not inside a container. Therefore:

- Do NOT run `--run-build` or modify `cli/scripts/` to emulate container builds.
- Stage the Linux `arm64` payload using `cli/scripts/build-receipt.mjs` in `clec-inspected-prebuilt-receipt` mode (`schemaVersion: 2`, `provenance.source.status = "not_verified_unknown"`, `provenance.buildInvocation.status = "not_verified_unknown"`), plus a separate retained `container-build-observation.json` recording the exact source commit (`3999d3ef...`), `native/` tree commit (`795deb33...`), read-only exported file SHA-256 hashes, pinned builder digest, kernel, `rustc --version --verbose`, `RUSTFLAGS`, executed `cargo` argv, stdout/stderr logs, output ELF SHA-256 digests, and `readelf`/`file` inspection results.

## Verifiable units and falsifiable predicates

1. **Unit 1: Capacity and pinned image pull.** Host free space, Docker `OSType=linux`, `Architecture=aarch64`, CPU/RAM, and pulled image IDs/RepoDigests match pinned digests.
2. **Unit 2: Isolated Linux `aarch64-unknown-linux-musl` MSRV 1.89.0 build and tests.**
   - Exported `native/` files match repo `HEAD` hashes (`Cargo.lock` SHA-256 `200070e2a526320a876dfecd70611583d654172ef87d59ce9d572e3aaf860cda`).
   - `cargo build --manifest-path /src/native/Cargo.toml --locked --release --bins -j 2` succeeds cleanly inside `rust:1.89.0-alpine3.22` producing `clec`, `clec-publish`, and `clec-validate` with static linkage (`RUSTFLAGS=-C target-feature=+crt-static` if required by Alpine `rustc` to eliminate `PT_INTERP`).
   - `file` and `readelf -h -l -d` prove ELF64 LSB `ARM aarch64`, zero `PT_INTERP` segments, and zero `DYNAMIC` / `NEEDED` shared-library entries.
   - `extractEmbeddedBuildIdentity` confirms `target: "aarch64-unknown-linux-musl"`, `profile: "release"`, `features: []`, `testHooks: false`, `rustcVersion` containing `1.89.0`, and matching `cargoLockSha256`.
   - `cargo test --manifest-path /src/native/Cargo.toml --locked -j 2` executes inside the builder container and all executed tests pass (recording exact test counts and any container-specific constraints).
3. **Unit 3: Schema v2 inspected-prebuilt staging and determinism.**
   - `cli/scripts/build-receipt.mjs` emits schema v2 `clec-inspected-prebuilt-receipt` for `linux-arm64`.
   - `cli/scripts/stage.mjs --allow-partial` produces identical `SHA256SUMS` across two independent runs (`staged-1`, `staged-2`), with `complete: false`, `publishable: false`, `linux-arm64` present (`musl-static`, `elf-64`, `aarch64-unknown-linux-musl`), four other targets `missing`, and byte-identical `cli/skills/clec/SKILL.md` (`66031f09781b0ed95f610e607719bca0967c067a546656d8da83b3dc90d4eb9b`) and `cli/README.md` (`e2a7ac9b3cce55848f8c7c802748cdedf0880738c1733a1df89d40e9be67dd74`).
4. **Unit 4: Authored UTF-8 fixture publishing (`--network none`).**
   - Tiny public authored UTF-8 fixtures (`Release A`, `Release B`, and tampered `Release B-corrupt`) include UTF-8 BOM, CRLF line endings, emoji (`😀`), Traditional Chinese (`退休`, `每年提領`), `0050`, `QQQ`, `4%`, subtitle `.srt`, and `.txt`/`.md` sources.
   - Linux `clec-publish` builds `Release A` and `Release B` inside `--network none` Linux container; Linux `clec-validate` validates both snapshots with exit 0.
5. **Unit 5: Real `glibc` AND `musl` Node 22 offline install and empty-PATH CLI execution (`--network none`).**
   - Executed separately in `node:22-bookworm-slim` (`glibc`) and `node:22-alpine` (`musl`), recording exact `/etc/os-release`, libc version (`ldd --version`), `uname -a`, `node -v`, and `npm -v`.
   - Negative installer controls inside Linux container: `--ignore-scripts` leaves non-working placeholder failing non-zero; wrong-tuple (`linux-x64` / macOS payload) and corrupt SHA-256 payload fail `install.mjs` closed and restore placeholder.
   - Isolated `npm install --global --offline` from `clec-cli-1.0.0-dev.0.tgz` into a temp prefix containing spaces and Unicode (`clec prefix 中文`) installs `bin/clec` linked to `bin/clec.exe` byte-identical to the static `clec` binary on both `glibc` and `musl`.
   - With `PATH=/nonexistent` (Node and Python absent from `PATH`, direct binary exec and installed npm `bin/clec` exec):
     - `--version`, `--help`, and `schema` succeed with `HOME` unset; `schema` reports `defaultConfigured: false` and `providerVerified: false`.
     - `status` fails with `INVALID_DATA_DIR` (exit 4) when `HOME` is unset without creating `./.local`.
     - `status` reports `ready: false` on a fresh `--data-dir`; `clec --offline sync --manifest ...` activates `Release A` (and second sync reports `reused: true`); `sources --canonical-only`, `search` (`0050 QQQ 4%`, `退休 提領 😀`), `read <actual-p_id> --context 1`, and `read <actual-s_id> --original --find ...` succeed and return exact UTF-8 byte spans matching raw fixture bytes.
     - `--max-bytes 1` fails with `OUTPUT_BUDGET_TOO_SMALL`; small `--max-bytes` on multi-item `read`/`search` reports `budget.omittedCount > 0`; `search --offline --sag2` fails cleanly with zero HTTP.
     - Tampered `Release B-corrupt` sync fails (`INTEGRITY_MISMATCH`) while preserving `Release A` active state and a pre-existing unknown marker file in `--data-dir`; concurrent sync lock contention preserves integrity without corrupting active state.
     - Pre/post checksums of fixture manifest/payload and non-target files remain unchanged.
6. **Unit 6: Cleanup and final reporting.**
